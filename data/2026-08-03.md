### [1] [From C to Idiomatic Rust: A Ship-of-Theseus Agentic Translation](https://arxiv.org/abs/2607.28835)
*Vasily A. Sartakov*

Main category: cs.SE

TL;DR: 本文提出了一种从C语言到Rust的迁移方法：先生成语义保持的非惯用Rust基线代码，再通过智能AI代理增量重写为惯用Rust，每一步通过编译和行为测试验证。在iodine项目（12.5k SLOC）上验证了该方法的可行性。


<details>
  <summary>Details</summary>
Motivation: C语言虽然性能优越、映射机器行为直接，但其内存安全完全依赖程序员，导致长期运行的C代码库中存在未定义行为、指针误用和生命周期错误等安全漏洞。Rust通过静态所有权和借用模型在编译期强制内存安全，但成熟的C系统无法直接翻译，因为隐式布局假设、别名模式和未定义行为需要先被重建才能生成安全的Rust代码。

Method: 提出两阶段迁移方法：(1) 先生成语义保持、非惯用的Rust基线代码；(2) 使用智能AI代理（agentic AI）增量地将基线代码重写为惯用Rust，每一步都通过编译验证和行为测试来确保正确性。

Result: 在iodine项目（12.5k SLOC的C代码库）上成功应用，证明了可靠的C到Rust迁移是一个结构化的转换工作流，而非单一的翻译步骤。

Conclusion: C到Rust的可靠迁移应当被视为一个多阶段、验证驱动的结构化流程：先建立语义等价的基线，再逐步演化到惯用代码，每一步都以编译和测试作为安全网，而非期望一次性翻译成功。

Abstract: C underpins operating systems, embedded platforms, and network infrastructure because its abstractions map directly to machine behaviour. Its explicit memory model, predictable data representations, and minimal runtime allow compilers to generate fast, deterministic code. These properties also leave correctness and memory safety entirely to the programmer, making undefined behaviour, pointer misuse, and lifetime errors persistent sources of defects and security vulnerabilities in long-lived C codebases. Rust eliminates most of failure modes through a static ownership and borrowing model that enforces memory safety and aliasing constraints at compile time. However, mature C systems cannot be translated directly: implicit layout assumptions, aliasing patterns, and undefined behaviour must be reconstructed before safe Rust can be produced.
  This paper presents a migration methodology that first generates a semantics-preserving, non-idiomatic Rust baseline and then incrementally rewrites it into idiomatic Rust using agentic AI, validating each step through compilation and behavioural testing. Applied to iodine (12.5k SLOC), the approach demonstrates that reliable C-to-Rust migration is a structured transformation workflow rather than a single translation step.

### [2] [High-Level Big Integer Arithmetic in Futhark for GPUs](https://arxiv.org/abs/2607.28897)
*Cosmin E. Oancea,Stephen M. Watt*

Main category: cs.SC

TL;DR: 本文报告了在Futhark这一高级函数式语言中，针对中等规模整数（2^15至2^19位）的GPU块级加减乘除运算实现。通过与手写C++/CUDA版本及CGBN库的对比，分析了哪些函数式构造编译效果良好、内存放置和串行化的有效性，以及所需的编译器支持。结果表明，高层代码能紧凑表达算法，在编译器改进后性能接近竞争水平，其中数组自动放置到GPU寄存器内存对性能至关重要。


<details>
  <summary>Details</summary>
Motivation: 在GPU上进行大整数运算（如密码学、数论计算）通常需要手写低级CUDA代码，开发效率低且难以维护。作者希望探索使用高级函数式语言Futhark来表达这类算法，评估其在性能和代码简洁性之间的权衡，并找出编译器需要哪些改进来支持这类高效计算。

Method: 在Futhark中实现了块级（block-level）的大整数加减乘除运算，使用中等规模（2^15至2^19位）的操作数。通过与手写C++/CUDA实现及CGBN库进行系统对比，分析不同函数式构造的编译效果、内存放置策略（特别是寄存器内存中的数组放置）、以及串行化操作的影响，进而确定所需的编译器改进。

Result: 研究发现高级函数式代码能够紧凑地表达大整数算法，在经过特定的编译器改进后性能可接近手写C++/CUDA和CGBN的实现。最关键的性能因素是编译器能否自动将数组放置在GPU寄存器内存中，这一自动化能力对达到竞争性性能至关重要。

Conclusion: 高级函数式语言有望成为GPU大整数运算的可行开发工具，前提是编译器提供针对性的支持，尤其是寄存器内存的自动管理。该工作为大整数算法的可移植高性能实现指明了方向，也为函数式语言编译器优化提供了具体目标。

Abstract: We report on GPU implementations of block-level addition, subtraction, multiplication and division for midsize integers, with operands of $2^{15}$ to $2^{19}$ bits using the high-level functional language Futhark. Comparing with hand-written C++/CUDA versions and CGBN, we identify which functional constructs compile well, where memory placement and sequentialization are effective, and what compiler support is needed. The results show that high-level code can express the algorithms compactly while approaching competitive performance after certain compiler improvements. In particular, we find that automated placement of arrays in GPU register memory is critical for performance.
