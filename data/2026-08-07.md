### [1] [Let it Flow: A Formally Verified Compilation Framework for Asynchronous Dataflow](https://arxiv.org/abs/2608.05451)
*Zhengyao Lin,Yi Cai,Milijana Surbatovich*

Main category: cs.PL

TL;DR: 本文提出Wavelet，首个对异步数据流架构编译器进行形式化验证的工作。它结合能力类型系统（带fence机制）和Lean形式化验证编译器核心pass，证明了前向模拟和确定性等关键性质。


<details>
  <summary>Details</summary>
Motivation: 数据流架构因功耗与性能的平衡而重新受到关注，但编译到数据流架构的过程容易出错，特别是需要在保持确定性的同时启用流水线优化。现有编译器缺乏形式化保证。

Method: 采用混合技术：前端使用新颖的能力类型系统（capability type system）配合fence机制来同步冲突的内存访问并启用流水线；后端使用Lean定理证明器对编译器的两个核心pass进行形式化验证，证明前向模拟和确定性性质，并通过语义传播前端类型系统的健全性保证来实现模块化。

Result: Wavelet编译生成的数据流图与未经验证的RipTide空间数据流架构优化编译器产生的图规模相当，表明形式化验证没有引入显著的编译效率损失。

Conclusion: Wavelet证明了异步数据流编译器可以被形式化验证，同时保持编译产物的质量与未验证编译器相当，为该领域的形式化验证方法奠定了基础。

Abstract: Dataflow architectures have gained renewed interest due to their balance between power efficiency and performance. In (spatial) dataflow architectures, a program is represented as a set of entirely distributed and dynamically scheduled dataflow operators that communicate through asynchronous channels, which greatly improves data locality and parallelism. However, compiling to dataflow architectures remains an error-prone process, in order to maintain determinacy while enabling pipelining. Determinacy means that the result of a dataflow program is deterministic and independent of the schedule of operator execution, and pipelining is an important optimization in spatial dataflow that enables parallelism across loop iterations.
  In this work, we present Wavelet, the first effort to formally verify a compiler for asynchronous dataflow. We use a mix of techniques to achieve this goal. Our frontend uses a novel capability type system with fences to synchronize conflicting memory accesses and enable pipelining. We then verify a Lean formalization of two core passes of our compiler that translates elaborated programs from the type checker to dataflow graphs, proving important properties of forward simulation and determinacy. Notably, our formalization semantically propagates the soundness guarantees of the frontend type system, ensuring modularity between simulation and determinacy proofs. In evaluation, we show that dataflow graphs compiled by Wavelet have comparable sizes to those produced by an unverified optimizing compiler for the RipTide spatial dataflow architecture.

### [2] [Learning Context-Free Grammars for Grammar-Constrained Decoding via Declarative Agentic Programming with Guarantees](https://arxiv.org/abs/2608.05493)
*Kevin Cheang,Geoff Hulette,Rahul Kumar,Felipe R. Monteiro,Federico Mora,Robin Salkeld,Lin Tan,Serdar Tasiran*

Main category: cs.PL

TL;DR: 本文提出Autogrammar，一个能自动从文档和执行数据中学习上下文无关文法的智能体，用于语法约束解码，使语言模型在低资源DSL中生成语法有效的程序，在三个DSL上取得近乎完美的精度，并显著提升端到端LM性能。


<details>
  <summary>Details</summary>
Motivation: 语言模型在与外部服务交互时经常需要生成特定领域语言(DSL)的程序，但DSL通常资源稀缺且晦涩难懂，导致LM频繁生成语法无效的程序。语法约束解码虽能消除此类失败，但需要目标语言的上下文无关文法，而对第三方DSL而言，这种文法很难获取。

Method: 将Autogrammar形式化为Kripke结构，其非确定性选择由语言模型解析，通过线性时序逻辑约束实现智能体行为的声明式控制。从文档和执行数据中自动学习上下文无关文法。

Result: 在三个DSL（Amazon CloudWatch Logs Insights、Dynatrace Query Language、Datadog Search Syntax）上评估四种Autogrammar版本：生成的文法在未见数据上达到近乎完美的精度；时序约束将执行时间减少3.8倍且无显著精度损失；执行数据至关重要而文档并非必需；在10个真实任务中8个显著提升端到端LM性能，匹配或超过专业维护的文法。现有LM基线和技术形式化技术生成的文法表现显著更差。

Conclusion: Autogrammar能够自动学习高质量的上下文无关文法，为语法约束解码提供可行方案，从而解决LM在低资源DSL上生成语法无效程序的问题，其性能甚至可以媲美专业人工维护的文法。

Abstract: Language models (LMs) are increasingly used to interact with external services via programs written in domain-specific languages (DSLs). Unfortunately, since DSLs are often low-resource and esoteric, LMs frequently produce syntactically invalid programs in these languages. Grammar-constrained decoding can eliminate such failures, but requires syntactic constraints. These are usually in the form of a context-free grammar for the target language, an artifact that is hard to come by for third-party DSLs. In this work, we define an agent, called Autogrammar, that automatically learns context-free grammars from documentation and execution data. Autogrammar is formalized as a Kripke structure whose nondeterministic choices are resolved by a language model, enabling declarative control of agent behavior via linear temporal logic constraints. We evaluate four versions of Autogrammar on three DSLs (i.e., Amazon CloudWatch Logs Insights, Dynatrace Query Language, and Datadog Search Syntax) and find that it generates grammars that achieve near perfect precision on unseen data; that temporal restrictions reduce execution time by 3.8x without incurring statistically-significant loss in precision; that execution data is crucial while documentation is dispensable; and that grammar-constrained decoding using Autogrammar-generated grammars significantly improves end-to-end LM performance on eight out of ten real tasks, matching or exceeding the performance of a professionally-maintained grammar. In comparison, the context-free grammars generated by existing LM baselines and a state-of-the-art formal technique perform significantly worse over the same evaluation.

### [3] [Noise-aware Verification and Synthesis of Quantum Programs](https://arxiv.org/abs/2608.05807)
*Stefanie Muroya,Krishnendu Chatterjee,Thomas A. Henzinger*

Main category: cs.PL

TL;DR: 本文提出了一种噪声感知的量子编程方法，考虑真实硬件中的噪声模型，建立了硬件相关的量子程序语义。研究者开发了噪声感知的量子霍尔逻辑，并基于此推导出有界验证和自动合成方法，用于合成噪声最优的无循环量子程序（如奇偶校验、量子态制备、量子态判别），并在IBM Qiskit硬件规格上进行了评估。


<details>
  <summary>Details</summary>
Motivation: 大多数量子编程研究都假设理想化的无噪声语义，但真实量子硬件存在噪声。为使量子程序的推理和验证贴合实际执行环境，需要建立硬件相关的噪声感知语义和形式化方法。

Method: 1) 提出噪声感知的量子霍尔逻辑（noise-aware quantum Hoare logic），为带噪声的量子程序提供逻辑推理框架；2) 基于该逻辑推导有界验证算法，用于在特定硬件上验证量子程序的正确性；3) 推导自动合成方法，生成噪声最优的无循环量子程序；4) 在IBM Qiskit的硬件规范上评估所提出的方法。

Result: 在IBM Qiskit工具包提供的硬件规格上完成了评估。实验发现：不同噪声模型下会得到不同的最优子程序；此外，合成工具表明经典概率分支在量子编程中对实现最优性是必要的。

Conclusion: 该工作从逻辑基础到自动验证与合成，系统性地研究了噪声感知量子编程，证明了考虑硬件噪声不仅能得到硬件特定的最优量子子程序，还揭示了经典概率分支在量子编程最优性中的关键作用。

Abstract: While most research on quantum programming considers an idealized, noise-free semantics for quantum programs, we reason about quantum programs that are executed on real, noisy hardware. We consider the error models published by quantum hardware vendors to give a hardware-dependent semantics to quantum programs. This work presents a comprehensive study of noise-aware quantum programming, ranging from logical foundations to automated verification and synthesis. We develop a noise-aware quantum Hoare logic, and use it to derive algorithmic methods for the bounded verification of quantum programs on specific hardware, and for the automatic synthesis of noise-optimal loop-free quantum programs. In this way, we synthesize hardware-dependent subroutines that commonly occur in quantum algorithms, such as parity checks, quantum state preparation, and quantum state discrimination. We evaluate our method on the hardware specifications provided by the IBM Qiskit toolkit. Besides finding different optimal subroutines for different noise models, our synthesis tool also shows that classical probabilistic branching is needed for optimality in quantum programming.

### [4] [Bit-Precise CHC Satisfiability Using Theory-Modular Reasoning](https://arxiv.org/abs/2608.05337)
*Omer Rappoport,Orna Grumberg,Yakir Vizel*

Main category: cs.LO

TL;DR: Mosaic是一个理论模块化框架，用于判定模固定位宽位向量理论（T_B）的约束Horn子句（CHCs）的可满足性。它通过将CHC集合划分为T_B和整数算术理论（T_I）两个片段，并以模块化方式推理、通过跨理论的声音翻译交换信息，最终判定原始CHC集合的可满足性。原型基于Z3和Spacer实现，在位操作基准测试上显著优于Spacer。


<details>
  <summary>Details</summary>
Motivation: 位精确的程序验证需要判定模固定位宽位向量理论的CHC可满足性，但现有的CHC求解器在处理T_B时往往表现不佳，限制了位精确推理的可扩展性。

Method: Mosaic采用理论模块化框架：1) 将模T_B的CHC集合划分为两个片段，分别解释在T_B和T_I上；2) 实现模块化推理算法，在两个片段间通过声音翻译交换信息；3) 综合判断原始CHC集合的可满足性。原型使用Z3和Spacer实现。

Result: 在位操作基准测试上的评估显示，Mosaic显著优于Spacer。

Conclusion: Mosaic通过将位向量和整数算术推理分离并模块化组合，有效提升了CHC在位向量理论上的可满足性判定性能，展示了理论模块化方法在位精确验证中的潜力。

Abstract: Deciding satisfiability of Constrained Horn Clauses (CHCs) modulo the theory of fixed-size bit-vectors ($\mathcal{T}_B$) is fundamental to bit-precise program verification. However, state-of-the-art CHC-solvers often struggle with $\mathcal{T}_B$, limiting scalability in bit-precise reasoning. We present Mosaic, a theory-modular framework for deciding satisfiability of CHCs modulo $\mathcal{T}_B$ by combining reasoning in $\mathcal{T}_B$ and the theory of Integer Arithmetic ($\mathcal{T}_I$). Given a CHC set modulo $\mathcal{T}_B$, Mosaic partitions it into two fragments interpreted over $\mathcal{T}_B$ and $\mathcal{T}_I$. Moreover, it implements an algorithm that reasons about the fragments in a modular fashion, exchanges information between them via sound translations across theories, and determines satisfiability w.r.t. the original CHC set. We implemented a prototype of Mosaic using Z3 and Spacer and evaluated it on bit-manipulating benchmarks. Our evaluation shows that Mosaic significantly outperforms Spacer on these benchmarks.

### [5] [PPDL: LLM-Based Flows as Probabilistic Programs](https://arxiv.org/abs/2608.05234)
*Louis Mandel,Guillaume Baudart,Mandana Vaziri,Martin Hirzel*

Main category: cs.LG

TL;DR: 本文提出了一种用于编程大语言模型(LLM)工作流的概率语言，使开发者能够量化和传播整个应用流程中的不确定性，并在不修改流程逻辑代码的情况下实验不同的推理扩展技术。


<details>
  <summary>Details</summary>
Motivation: 构建基于LLM的可靠应用仍然面临重大挑战：LLM输出缺乏准确性和置信度度量，这种不确定性在多次LLM调用和工具调用的流程中被放大，导致开发者和最终用户难以信任结果。

Method: 提出一种概率编程语言，用于描述LLM工作流，能够量化并在整个流程中传播不确定性，同时支持不同的推理扩展技术（inference scaling techniques）的实验，无需在流程逻辑之外添加额外代码。

Result: 通过实验研究展示了该语言的能力，并进行了针对Rocq定理证明器的定理证明智能体的案例研究。

Conclusion: 该概率语言为构建可靠LLM应用提供了一种新的编程范式，使不确定性管理成为流程设计的一等公民，并通过案例研究验证了其在定理证明等复杂场景中的实用性。

Abstract: Building reliable applications that leverage large language models (LLMs) remains a significant challenge. While LLMs offer impressive capabilities across diverse tasks, their outputs often lack accuracy and provide no clear measure of confidence. This uncertainty compounds in flows of multiple calls to LLMs and other tools, making it difficult for developers and end-users to trust the results. This paper introduces a probabilistic language for programming LLM-based flows. It enables developers to quantify and propagate uncertainty throughout the application's flow, and experiment with different inference scaling techniques without adding a single line of code beyond the flow's logic. We present an experimental study to demonstrate this capability, and a case study building a theorem proving agent for the Rocq theorem prover.

</details>
