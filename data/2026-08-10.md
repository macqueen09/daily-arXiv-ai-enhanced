### [1] [Agentic Planning for Symbolic Execution](https://arxiv.org/abs/2608.06397)
*Daniel Koh Ji Yang,Yannic Noller,Corina S. Pasareanu,Youcheng Sun*

Main category: cs.PL

TL;DR: 本文提出Agolic，一个基于智能体规划的系统，通过利用先前有界符号执行（BSE）运行的证据来选择和配置后续运行，从而扩展符号执行的实际覆盖范围。在C/C++程序上的评估显示，Agolic平均覆盖了连续符号执行3倍以上的分支数，且在六个程序中覆盖了所有对比方法语料库中未触及的分支。


<details>
  <summary>Details</summary>
Motivation: 符号执行虽力求探索所有可行程序路径，但实际运行中资源耗尽时仍有大量程序行为未被覆盖。现有方法仅关注单次运行内的状态探索，忽略了跨多次有界运行之间的推理与规划潜力。

Method: Agolic是一种智能体规划系统：它利用之前BSE运行的证据（如覆盖率回放、源代码、先前定位尝试）来选择并配置后续的有界符号执行运行，底层符号执行工具负责具体的状态探索。规划智能、可用证据和执行模式均可根据符号执行工具和分析目标进行适配。其中一种适配使用LLM智能体进行分支覆盖率探索。

Result: 在多个C和C++程序上的评估中，Agolic在所有程序上都扩展了连续符号执行获得的分支覆盖率，平均覆盖3倍以上的分支。它比覆盖率引导的模糊测试和基于编译器的混合符号执行语料库覆盖更多分支，并且在七个程序中的六个上触及了所有对比方法语料库中都不存在的分支。

Conclusion: 现有符号执行工具存在大量未开发的潜力，通过跨运行推理其能力的使用方式（而非干预底层状态选择）即可实现显著覆盖提升，为符号执行的实用化提供了互补的新方向。

Abstract: Symbolic execution seeks to explore feasible program paths, yet a practical run may exhaust its resources while much program behaviour remains unreached. We investigate a complementary way of extending its practical reach by reasoning about how the same tool is utilised from one bounded run to the next, while leaving ordinary state exploration to the underlying tool. We present Agolic, an agentic planning system that uses evidence from earlier runs to choose and configure later bounded symbolic execution (BSE) runs, which the underlying symbolic execution tool then carries out. The planning intelligence, available evidence and execution modes can be adapted to the symbolic execution tool and analysis objective. We evaluate one adaptation for branch-coverage exploration, in which an LLM-based agent reasons over source code, replayed coverage and earlier targeting attempts. We evaluate Agolic on several C and C++ programs. On every program, it extends the branch coverage obtained by continuous symbolic execution and covers more than $3\times$ as many branches on average. It also covers more branches than each individual corpus from coverage-guided fuzzing and compiler-based concolic execution in our evaluation and reaches branches absent from all comparison corpora combined on six of the seven programs. Taken together, these results point to considerable untapped potential in existing symbolic execution tools, some of which may be realised by reasoning about how their capabilities are used across runs while leaving state selection during ordinary symbolic exploration to the underlying tool.

### [2] [PyFlow: An Inter-procedural Static Analysis Framework for Python](https://arxiv.org/abs/2608.07026)
*Zinan Gu,Haoxiang Yan,Peisen Yao*

Main category: cs.PL

TL;DR: PyFlow是一个基于IFDS框架的Python静态分析框架，通过多阶段IR流水线和可参数化的抽象域泛型求解器，实现了高精度的污点分析，在合成和真实基准上均超越了八种主流SAST工具。


<details>
  <summary>Details</summary>
Motivation: Python的动态特性（动态分派、一等函数、元编程、异常、描述符和属性驱动查找）使得精确的跨过程静态分析极具挑战性，现有工具在分析效果上存在不足。

Method: PyFlow提供多阶段中间表示流水线，以及由抽象域参数化的通用IFDS求解器。分析开发者只需实现数据流语义，框架自动构建超级图、执行不动点迭代并缓存摘要。

Result: 在与八种Python SAST工具（DevSkim、Dlint、Bandit、Bearer、CodeQL、Pysa、Semgrep、Snyk）的对比中，PyFlow在合成基准上取得最佳综合召回率和F1分数；在真实基准上获得最高召回率和F1分数，同时保持与污点分析引擎相当的精确度。

Conclusion: PyFlow证明了IFDS框架配合良好设计的IR流水线能够有效应对Python语言的动态特性挑战，并为构建Python静态分析提供了经验教训。

Abstract: Static program analysis infers program properties automatically. Yet precise interprocedural analysis remains challenging, and dynamically typed languages amplify the difficulty. Python is particularly problematic: dynamic dispatch, first-class functions, metaprogramming, pervasive exceptions, and an object model based on descriptors and attribute-driven lookup collectively impede precise reasoning.
  We present PyFlow, a generic IFDS-based static-analysis framework for Python. PyFlow provides a multi-stage intermediate-representation pipeline and a generic IFDS solver parameterized by abstract domains. Analysis developers implement only the dataflow semantics; the framework constructs the supergraph, performs fixed-point iteration, and caches summaries.
  We implement a taint analysis in \pyflow and evaluate it against eight Python SAST tools (DevSkim, Dlint, Bandit, Bearer, CodeQL, Pysa, Semgrep, and Snyk) on the synthetic and real-world benchmarks from a recent ICSE~'26 study. On the synthetic benchmark, PyFlow achieves the best aggregate recall and F1 score among all nine tools. On the real-world benchmark, it attains the highest recall and F1 score while maintaining precision competitive with taint-based engines. We conclude with lessons learned from building IFDS analyses for Python.
