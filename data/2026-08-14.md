### [1] [A Rig of Transformations](https://arxiv.org/abs/2608.12409)
*Emma Tye*

Main category: cs.PL

TL;DR: 本文提出将有限代数数据类型建模为交换半环（commutative rig），其中半环等式对应数据类型之间的同构关系，并可通过部分同构来建模数据类型的嵌入（如位填充）。


<details>
  <summary>Details</summary>
Motivation: 在高级函数式语言中，编译器通常不给予用户对数据类型运行时表示的控制权。然而程序层面的数据结构建模方式与二进制层面的表示需求（出于效率或遗留原因）往往不同。因此，能够描述数据布局及其变换是编程中有用且必要的，但做到正确、高效且符合人体工程学却十分困难。

Method: 作者将有限代数数据类型建模为一个交换半环（即无加法逆元的环）。在半环框架中，等式由数据类型之间的同构来建模。通过这种抽象，数据类型嵌入到更大类型（如位填充）可以被建模为部分同构。

Result: 该模型能够用代数结构统一描述数据布局及其变换，支持将位填充等操作形式化为部分同构关系。

Conclusion: 通过交换半环的代数框架，可以为高级语言中的数据类型布局变换提供形式化且可组合的描述方法，兼顾正确性、效率与可用性。

Abstract: In high-level functional languages, the compiler often gives users little control over the runtime representation of data types. Yet how we model data structures at the program level can be different to how we want to represent them at the binary level, for efficiency or legacy reasons. Hence being able to describe data layouts and their transformations for data types is a useful and necessary part of programming, but difficult to do correctly, efficiently and ergonomically. We present a model of finite algebraic data types as a commutative rig (a ring without additive inverses), where the rig-equalities are modelled by isomorphisms between data. Using this approach, we can also model embedding a data type into a larger type (e.g. bit-padding) as a partial isomorphism.

</details>


### [2] [Stream-based Online and Offline Monitoring under Measurement Noise](https://arxiv.org/abs/2608.13211)
*Bernd Finkbeiner,Martin Fränzle,Florian Kohn,Paul Kröger*

Main category: cs.PL

TL;DR: 本文提出RLola，一种基于流规范语言Lola的鲁棒扩展。RLola引入松弛变量（slack variables）符号化表示传感器测量噪声，避免了区间算术的别名问题。作者提出了在线和离线两种监控算法，识别了可保证常数内存的RLola子片段，并在现有RTLola框架中实现和评估。


<details>
  <summary>Details</summary>
Motivation: 现有的流式监控方法（如Lola）假设输入流的值是完全准确的物理测量，但实际传感器存在测量噪声和误差，这些误差会在监控器的处理和聚合步骤中被进一步放大。因此需要一种能够鲁棒处理测量噪声的流式规范语言和监控方法。

Method: 1) 在Lola中引入松弛变量，符号化表示测量噪声，避免区间算术的别名问题；2) 提出在线监控算法，实时反馈系统状态；3) 提出基于SMT的离线算法，分析完整系统轨迹，判断是否存在满足所有断言的地面真值轨迹；4) 识别可自动转换为常数内存监控器的RLola富片段；5) 在现有RTLola框架中实现。

Result: 在RTLola框架中实现了在线和离线监控算法，并通过综合示例评估了其精度和运行时间。离线算法能够检测到在线算法可能遗漏的违规情况。

Conclusion: RLola通过松弛变量有效解决了传感器噪声对流式监控的影响，在线和离线算法互补——在线提供实时反馈，离线提供更全面的违规检测能力，同时保证了常数内存监控的可行性。

Abstract: Stream-based monitoring is a runtime verification approach for cyber-physical systems that translates streams of input data, such as sensor readings, into streams of aggregate statistics and verdicts about the safety of the system. It is usually assumed that the values on the input streams represent fully accurate measurements of the physical world. In reality, however, physical sensors are prone to measurement noise and errors. These errors are further amplified by the processing and aggregation steps within the monitor. This paper introduces RLola, a robust extension of the stream-based specification language Lola. RLola incorporates the concept of slack variables, which symbolically represent measurement noise while avoiding the aliasing problem of interval arithmetic.
  We present algorithms for both online and offline monitoring of RLola specifications. Since monitoring RLola specifications may require unbounded memory in general, we identify a rich fragment of RLola that can be automatically translated into monitors with guaranteed constant memory usage for online monitoring. An online RLola monitor observes a live system and provides real-time feedback on the current status of specified assertions. A satisfiability-modulo-theories-based offline algorithm analyzes complete system traces and determines whether a hypothetical ground-truth trace exists that satisfies all assertions at all time points. The offline algorithm can therefore detect violations that the online algorithm may miss. We implement these algorithms in the existing RTLola framework and evaluate their precision and running time based on a comprehensive example.

</details>


### [3] [Multiobjective Preexpectation Reasoning for Probabilistic Programs](https://arxiv.org/abs/2608.13268)
*Lena Verscht,Hannah Mertens,Kevin Batz,Sebastian Junges,Benjamin Lucien Kaminski,Joost-Pieter Katoen*

Main category: cs.PL

TL;DR: 本文研究了带有不确定性的概率程序中的多目标策略综合问题，提出了一种基于演绎的、程序级的方法。核心是引入多目标预期望变换器（multiobjective preexpectation transformer），它将一个后期望元组映射到可实现值的集合（凸 Hoare 幂域的元素），用于求解帕累托前沿上的最优策略。该方法保守地扩展了最弱预期望，并提升标准循环规则，通过混合确定化（randomizing over non-probabilistic determinizations）合成见证策略。该框架对操作型 MDP 语义是可靠的，且不要求有限状态空间，可视为对无限 MDP 进行多目标优化的符号化方法。


<details>
  <summary>Details</summary>
Motivation: 现有的概率程序验证与策略综合方法大多针对单一目标（单目标期望优化），而实际规划问题往往需要同时优化多个目标（如成本与收益、时间与资源），需要沿帕累托前沿进行权衡。然而多目标设置下的策略合成本身缺乏程序级（deductive/program-level）的形式化方法，现有工作多依赖有限状态 MDP 或枚举方法。

Method: 本文提出多目标预期望变换器，将多个后期望映射到可实现值的集合（凸 Hoare 幂域中元素），扩展了经典最弱预期望逻辑。发展循环规则和混合确定化策略合成规则，即通过随机化若干非概率确定化来生成最优策略。所有规则在操作 MDP 语义下证明可靠，且不限定状态空间有限。

Result: 证明了变换器和策略合成规则的可靠性；通过多项案例研究展示了该机制在程序层面的应用，可对无限状态 MDP 进行符号化多目标优化。

Conclusion: 本文提供了一套完整的、程序级的推理框架来应对多目标概率程序中的策略综合，兼具理论可靠性和实用表达能力，为无限 MDP 上的多目标优化提供了新的符号化途径。

Abstract: Probabilistic programs with nondeterminism model planning problems in which a strategy resolves the nondeterminism to optimize an expected outcome. We study the multiobjective setting, optimizing several outcomes at once along a Pareto front, and provide a deductive, program-level account of strategy synthesis. Its core is a multiobjective preexpectation transformer mapping a tuple of postexpectations to the set of simultaneously achievable values, an element of the convex Hoare powerdomain. It conservatively extends weakest preexpectations and lifts standard loop rules. We develop rules to synthesize witnessing strategies as mixed determinizations that randomize over non-probabilistic determinizations. We prove the transformer and synthesis rules sound against an operational MDP semantics, without requiring a finite state space: our approach can be seen as a symbolic approach - at program level - for multiobjective optimization over infinite MDPs. We demonstrate our machinery using various case studies.

</details>

### [4] [InSPECtor: Improving SLEIGH Processor Specification Veracity via Proxy](https://arxiv.org/abs/2608.13042)
*Michael Chesser,Paul Quirk,Douglas Cooke,Guy Farrelly,Surya Nepal,Damith C. Ranasinghe*

Main category: cs.CR

TL;DR: 本文提出了一个名为InSPECtor的自动化测试框架，首次系统性地验证开源SLEIGH处理器规范的正确性。该框架通过代理（proxy）方式自动生成Oracle验证策略，利用规范自身结构枚举可解码指令形式并生成目标初始状态，然后将执行规范的模拟器与硬件参考进行差分测试。在x86-64、AArch64、ARM/Thumb、RISC-V、MSP430等5种规范上发现超过38,920处差异，整理出125个独特缺陷并提出了修复方案，最终提炼出8条改进建议。


<details>
  <summary>Details</summary>
Motivation: 处理器规范是反汇编器、反编译器、模拟器等安全分析和程序分析工具的关键支撑，但规范的正确性很少被检验。规范中的错误会扭曲程序行为、掩盖漏洞，甚至被利用来规避分析。现有研究缺乏对Ghidra所用SLEIGH规范的系统性验证方法。

Method: 设计并实现了基于自动Oracle代理验证策略的测试框架InSPECtor。核心方法包括：(1)利用规范自身编码结构枚举可解码的指令形式并生成针对性的初始状态；(2)通过差分测试，将执行处理器规范的模拟器与硬件参考进行对比，验证指令解码和模拟执行的一致性。

Result: 在x86-64、AArch64、ARM/Thumb、RISC-V、MSP430五种开源规范上发现了超过38,920处差异，归纳为125个独特缺陷（含解码缺陷、语义缺陷和跨厂商不一致问题）并提供修复方案。研究还提炼出8条具体建议以推动未来改进。

Conclusion: 处理器规范的正确性对下游安全工具至关重要，InSPECtor提供了一种实用的自动化验证工具，能够显著提升SLEIGH处理器规范的保真度，从而增强下游安全和分析工具的可靠性。

Abstract: Processor specifications underpin critical security and program- analysis tools such as disassemblers, decompilers, and emulators, yet, their correctness is rarely examined. Errors in specifications distort program behaviour, obscure vulnerabilities, and enable analysis-evasion techniques. Validating processor specifications is a non-trivial task. Our study is a significant undertaking to enable, for the first time, the systematic validation of open-source SLEIGH language specifications, predominantly used by Ghidra. We design and implement a testing framework based on an automated oracle validation strategy by proxy. Our approach leverages the structure encoded in a specification itself to enumerate decodable instruction forms and generate targeted initial states. Then differentially test the successful decoding and emulation of those instructions by comparing emulators exercising the processor specification against hardware references.
  Applying InSPECtor across diverse, open-source specifications---x86-64, AArch64, ARM/Thumb, RISC-V, MSP430---embedding differences in specification styles, author preferences, and instruction set architecture designs, we uncovered over 38,920 discrepancies that led to 125 unique bugs with proposed fixes, identifying decoding and semantic defects as well as cross-vendor inconsistencies. We distill our findings into 8 concrete recommendations to drive future improvements. Our work underscores the importance of specification correctness and provides a practical tool to substantially improve the fidelity of SLEIGH processor specifications, strengthening the reliability of downstream security and analysis tools.

</details>

### [5] [Vero: Can AI Agents Build Formally Verified Software Repositories?](https://arxiv.org/abs/2608.13522)
*Zhe Ye,Hantao Lou,Yuechun Sun,Peiyang Song,Zhengxu Yan,Timothe Kasriel,Qingyang Zhang,Kaiyu Yang,Soonho Kong,Jingxuan He,Dawn Song*

Main category: cs.LG

TL;DR: Vero是首个在仓库级别评估"联合实现与证明合成"的基准测试，包含43个来自真实项目的多模块实例（跨越Python、Dafny、Verus和Coq），每个实例提供预定义API接口、人工策划的形式化规范及参考实现。最强的智能体只能解决43个实例中的27个，在最难的仓库上无法闭合任何规范，表明当前智能体在仓库级验证软件合成方面仍有显著不足。


<details>
  <summary>Details</summary>
Motivation: AI编程智能体无法保证生成代码的正确性，而现有的验证代码生成基准要么只聚焦单个函数，要么只评估在给定实现下的证明生成，尚不清楚智能体能否在真实多模块代码库中做出连贯的实现与证明选择。

Method: 构建包含43个多模块Lean 4仓库实例的基准，来源覆盖真实世界项目（密码协议到分布式系统），每个实例含预定义API接口、手工形式化规范和参考实现；支持仅证明和代码+证明两种评估模式；引入审计机制，允许智能体正式证明规范不可满足性或参考代码不正确，以揭示和修正策划阶段潜在的代码与规范错误。

Result: 评估了配备Lean工具链的前沿编码智能体配置，最强的智能体仅完全解决43个实例中的27个，在最难的仓库上未能闭合任何规范。

Conclusion: Vero为衡量向仓库级验证软件合成进展提供了具体测试平台，当前智能体在此任务上仍存在明显不足。

Abstract: AI agents are increasingly used for programming, but do not provide any guarantee on the correctness of generated code. Verified code generation, in which an agent produces both an implementation and a machine-checked proof of its specification, offers a stronger path toward trustworthy AI-generated software. Existing benchmarks in this direction either focus on individual functions or only evaluate proof generation with provided implementations. It is still an open question whether agents can make coherent implementation and proof choices across real multi-module codebases. To bridge this gap, we introduce Vero, the first benchmark to evaluate joint implementation and proof synthesis at the repository level. Vero contains 43 multi-module instances sourced from real-world repositories spanning Python, Dafny, Verus, and Coq, and covering diverse domains from cryptographic protocols to distributed systems. Each instance consists of a multi-module Lean 4 repository with predetermined API interfaces, manually curated formal specifications, and reference implementations, supporting both proof-only and code-and-proof evaluation modes. To improve benchmark reliability, Vero also includes an audit mechanism where agents are allowed to formally prove unsatisfiability of provided specification or incorrectness of reference code, which surfaces and corrects latent code and specification errors during curation. We evaluate frontier coding-agent configurations with Lean toolchain access. The strongest agent fully solves only 27 of 43 instances and closes no specifications on the hardest repositories. Vero provides a concrete testbed for measuring progress toward repository-scale verified software synthesis, where current agents still fall short. We release the benchmark, curation pipeline, and evaluation harness at https://github.com/sunblaze-ucb/vero.

</details>
