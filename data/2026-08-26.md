### [1] [IncSFS: Incremental Full-Sparse Flow-Sensitive Pointer Analysis for C/C++](https://arxiv.org/abs/2608.24391)
*Kunlin Liu,Zhenbang Chen,Piyi Zu,Yide Du,Ji Wang*

Main category: cs.PL

TL;DR: 本文提出IncSFS，首个针对C/C++程序的增量式全稀疏流敏感指针分析算法，通过将值流图转换为约束图并检测强连通分量来保证精度，交错传播点集增加和减少，支持单次分析中处理代码删除和插入，实验显示平均加速9.60x（对比全流敏感分析）和5.84x（对比重置重算方法），相比最先进的增量算法效率提升15.8%。


<details>
  <summary>Details</summary>
Motivation: 流敏感指针分析精度高但难以扩展到大型项目，且在软件持续演化的快速迭代场景中需要高效的分析方法。现有的增量指针分析算法在传播点集变化时效率不足，缺乏同时支持代码删除和插入的单次分析方案。

Method: IncSFS首先将值流图转换为约束图，执行强连通分量检测以保证精度；然后以交错方式传播点集增加和减少的变化，从而支持代码删除和插入在单次分析中完成。算法在分析期间点集关系保持对象无环时，保证终止并计算最小不动点。

Result: 在六个大型真实世界项目上的实验表明，IncSFS是精确且高效的：相比全流敏感指针分析实现平均9.60x加速，相比传统的重置重算方法实现5.84x加速，相比最先进的传播点集变化的增量指针分析算法效率提升15.8%。

Conclusion: IncSFS作为首个增量全稀疏流敏感指针分析算法，有效解决了大规模C/C++程序在持续演化场景下的分析效率问题，兼顾精度与性能，为快速迭代的软件开发提供了高效的分析支持。

Abstract: Pointer analysis is a fundamental technique for compiler optimization and program analysis. Flow-sensitive pointer analysis provides high precision but is difficult to scale to large projects. Tailored for rapid iteration scenarios where software evolves continuously, we introduce IncSFS, the first incremental full-sparse flow-sensitive pointer analysis algorithm for C/C++ programs. IncSFS first transforms the value-flow graph into a constraint graph and performs strongly connected component detection to ensure precision. It then propagates increases and decreases in points-to sets in an interleaved manner, supporting code deletion and insertion within a single analysis pass. IncSFS is guaranteed to terminate and compute the least fixed point when the points-to relation remains object-acyclic during analysis. Experiments on six large-scale real-world projects show that IncSFS is precise and efficient, achieving average speedups of 9.60x over full flow-sensitive pointer analysis and 5.84x over the traditional reset-recompute approach. It also improves efficiency by 15.8% over state-of-the-art incremental pointer analysis algorithms that propagate points-to-set changes.

### [3] [MGQL: An Executable, Small-Step Semantics of GQL](https://arxiv.org/abs/2608.24565)

Main category: cs.PL

TL;DR: 本文提出了MGQL，这是第一个基于ISO/IEC 39075标准的、针对GQL（图查询语言）可读片段的形式化小步操作语义。MGQL建模了多图属性图、混合边方向性，支持量化路径、标签表达式、模式列表和复合查询等GQL模式构造，并配有模式感知的类型系统，证明了类型系统的可靠性。


<details>
  <summary>Details</summary>

Method: MGQL提供了第一个机械化的小步操作语义，覆盖GQL大批可读片段：包括多图属性图（含混合边方向性）、量化路径和边、有向/无向匹配、标签表达式、模式列表和复合查询。同时设计了一个模式感知的类型系统，通过闭图模式细化变量类型，跟踪可空性，支持多个复合查询操作符，并以列表类型建模量化路径绑定。最终证明了类型系统的可靠性（soundness），确保良构查询的结果符合其声明的模式。

Result: MGQL为GQL的非正式规范与机械化实现之间建立了第一座桥梁，通过形式化语义和可靠的类型系统提供了端到端保证：良构查询产生的结果符合声明模式。这是首个支持该语义和语法复杂度的GQL形式化。

Conclusion: MGQL是连接GQL非正式标准与机械化实现的首次尝试，使关于正确性的形式化推理成为可能。它证明了在保留GQL核心语义和语法复杂性的前提下进行机械化形式化是可行的。

Abstract: ISO Graph Query Language (GQL) is the first international standard for property graph-based graph query languages, standardized as ISO/IEC 39075 in 2024. However, ISO/IEC 39075 codifies its semantics informally across 600+ pages of prose, making it difficult to formally reason about the standard or for a standard-faithful implementation. Existing formalizations are not adequate because they either: (1) significantly reduce the semantic complexity by omitting bag semantics, schemas, and composite queries on multiple graphs; (2) or significantly reduce the syntactic complexity by only considering isolated fragments such as pattern-matching, leaving the full query pipeline unformalized. Yet it is these semantic-syntactic features that make formalizing GQL non-trivial. We present MGQL, the first mechanized, small-step operational semantics for a substantial read-only fragment of GQL that is grounded in the ISO/IEC 39075 standard. Our formalization models multi-graph property graphs with mixed edge directionality and supports a large fraction of GQL pattern constructs: quantified paths and edges, directional and undirected matching, label expressions, pattern lists, and composite queries. The semantics is supported by a schema-aware type system that refines variable types via closed-graph schemas, tracks nullability, supports multiple composite query operators, and models quantified-path bindings with list types. We prove that our type system is sound, ensuring an end-to-end guarantee of well-formed queries yielding results that conform to their declared schemas. MGQL provides the first bridge between GQL's informal specification and a mechanized implementation, enabling formal reasoning about correctness.

### [4] [Algorithmic Cost in "Exact Real Computation"](https://arxiv.org/abs/2608.23603)

TL;DR: 本文定量加强了精确实计算（ERC）的图灵完备性：通过为ERC的操作原语分配比特成本，证明了任何在ERC中多项式成本可计算的实函数等价于在多项式时间内图灵可计算，并在iRRAM C++库中通过运行时测量验证了理论预测。


<details>
  <summary>Details</summary>
Motivation: ERC先前已被证明与图灵机在定性（复杂度类）层面等价，但缺乏定量（多项式时间）层面上的严格对应关系。本文旨在弥合这一差距，从定性等价提升到强 Church-Turing 假设所要求的多项式时间等价。

Method: 为ERC的操作原语（包括部分/多值测试）分配比特成本，建立成本模型，使得ERC中的多项式成本计算与图灵机的多项式时间计算形成双向对应关系；并在iRRAM C++库的实现上进行运行时测量以验证理论预测。

Result: 成功建立了ERC与图灵机之间的多项式时间等价性：任何在ERC中多项式成本可计算（计算成本为输入比特数的多项式函数）的实函数，也能在图灵机上多项式时间内计算，反之亦然；iRRAM实现上的运行时测量与理论预测一致。

Conclusion: ERC不仅在定性上等价于图灵机，而且在定量（多项式时间）层面上也满足强Church-Turing假设的要求，进一步巩固了ERC作为一种实用且理论上严谨的连续数据编程范式的地位。

Abstract: Turing completeness of a programming language or system characterizes its expressive power; and the strong Church-Turing hypo-/thesis refines such from qualitative to polynomial-time equivalence. Exact Real Computation (ERC) is a novel numerical programming language paradigm: for the imperative processing of continuous data as entities appearing as exact, i.e. devoid of rounding errors [doi:10.1007/978-3-662-44199-2_107]. ERC has been designed [doi:10.46298/lmcs-20(2:17)2024] as convenient and practical alternative, namely proven qualitatively equivalent, to the Turing machines originally underlying Computable Analysis [doi:10.1007/978-3-642-56999-9,doi:10.1007/978-1-4684-6802-1].
  The present work quantitatively strengthens this qualitative Turing-completeness: We assign bit-costs to ERC's operational primitives (including partial/multivalued tests) in such a way that any real function incurring polynomial cost becomes Turing-computable in polynomial time, and vice versa. Runtime measurements on implementations in the iRRAM C++ library confirm our theoretical performance predictions.
