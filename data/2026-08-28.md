### [1] [A Programming Paradigm for Spatiotemporal Composability](https://arxiv.org/abs/2608.25512)
*Yifan Shi,Wei Zhang,Tianyi Cui*

Main category: cs.PL

TL;DR: 本文针对现代软件（如插件系统、自演化智能体）中动态组合缺乏形式化基础的问题，提出两个正交维度：时间可组合性（完全回滚组件副作用）和空间可组合性（声明并响应式管理组件间依赖）。通过将经典的effect和coeffect概念提升为运行时机制——可逆effect（每个上下文变换携带逆变换）和响应式coeffect（依据组件的coeffect规范对上下文变化分类以驱动激活/停用），并将两者统一为单一上下文类型，形成"上下文范式"（context paradigm），最终给出动态组合演算及其实施Cordis元框架。


<details>
  <summary>Details</summary>
Motivation: 现代软件系统越来越依赖动态组合（如插件系统、自演化agent harnesses），但动态组合的形式化基础发展不足，缺乏对组件时间维度（副作用回滚）和空间维度（依赖管理）的系统性理论支撑。

Method: 1) 形式化可逆effect：每个上下文变换携带运行时持有的逆变换，实现单组件局部的时间可组合性；2) 形式化响应式coeffect：依据组件的coeffect规范对上下文变化分类，驱动组件激活/停用，实现单组件局部的空间可组合性；3) 将effect上下文与coeffect上下文统一为单一上下文类型，通过所有effect和coeffect的中介产生观测等价性；4) 组合为"组件"概念，给出动态组合演算，其元理论将时空可组合性从单个组件提升到整个交错组件系统；5) 实现Cordis元框架，包含effect追踪、coeffect解析核心库，以及带配置调和与热模块替换的声明式组件加载器。

Result: 构建了统一的上下文类型，使不同组件的effect交错时在观测等价下互不干扰；给出了动态组合演算及其元理论，证明时空可组合性可从单组件扩展到整个系统；并通过Cordis框架进行了具体实现验证。

Conclusion: 通过可逆effect与响应式coeffect的统一，建立了动态组合的形式化基础——"上下文范式"，实现了从单组件到多组件系统的时空可组合性保证，并提供了Cordis这一实际可用的元框架。

Abstract: Modern software -- from plugin systems to self-evolving agent harnesses -- increasingly requires dynamic composition, yet its formal foundations remain underdeveloped. We identify two orthogonal dimensions of the problem: temporal composability, the ability to completely revert a component's side effects upon removal, and spatial composability, the ability to declare and reactively manage inter-component dependencies. We address the two dimensions by lifting classical effect and coeffect concepts to runtime mechanisms. In particular, we formalize revertible effects, in which every context transformation carries an inverse that the runtime holds, establishing temporal composability local to one component. We formalize reactive coeffects, in which every context change is classified against a component's coeffect specification to drive its activation and deactivation, establishing spatial composability local to one component. We then unify the effect context and the coeffect context into a single context type and mediate every effect and coeffect through it, yielding a discipline we call the context paradigm; the mediation induces an observational equivalence up to which the effects of distinct components interleave without disturbing one another. Combining these mechanisms into the notion of a component, we give a calculus of dynamic composition whose metatheory carries spatiotemporal composability from a single component to a whole system of interleaved components. We implement these ideas in Cordis, a meta-framework of spatiotemporal composability that provides a core library with effect tracking and coeffect resolution, as well as a declarative component loader with configuration reconciliation and hot module replacement.

### [2] [DataKernelBench: Can LLMs Optimize Database Queries on GPUs?](https://arxiv.org/abs/2608.25061)
*Gokul Karthik Kumar,Yotam Perlitz,Corey Lammie,Andrea Giovannini,Katja Hose*

Main category: cs.CL

TL;DR: 本文提出DataKernelBench，一个将SQL翻译为PyTorch TorchPlan程序并评估LLM优化数据库风格算子的基准测试框架。在TPC-H SF10上，最强的全查询CUDA配置相比torch.compile实现了2.11倍加速且达到完全通过率；扩展到TPC-H SF100（四个H100 GPU）时通过Dask-cuDF实现2.54倍加速。


<details>
  <summary>Details</summary>
Motivation: 现有LLM内核基准测试聚焦于机器学习算子，忽略了数据库风格算子（不规则、异构、数据移动密集）的测试。而数据库系统越来越依赖GPU加速，但查询级峰值性能仍依赖手写内核，缺乏系统化的LLM内核生成基准来评估该场景。

Method: 将SQL翻译为经过验证的PyTorch TorchPlan程序，评估LLM优化核心张量片段或完整查询，支持CUDA和Triton两种后端，并通过执行引导修复（execution-guided repair）来迭代改进。为处理超出GPU内存的数据，使用Dask-cuDF扩展TorchPlan实现按需分区加载。

Result: 在TPC-H SF10（H100 GPU）上，最强的全查询CUDA配置获得2.11倍加速且完全通过率。在TPC-H SF100（四个H100 GPU）上通过Dask-cuDF实现2.54倍加速。高性能实现通常采用内核融合和执行策略改变，更强模型受益于全查询特化，工作负载上下文比硬件上下文更重要。

Conclusion: DataKernelBench填补了LLM内核生成在数据库风格算子上的空白，证明了LLM能够生成高质量的数据库查询内核，并揭示了全查询特化、内核融合等工作负载感知策略是提升性能的关键因素。

Abstract: GPUs increasingly accelerate database systems, but query-specific peak performance still often relies on hand-written kernels. Existing LLM kernel benchmarks focus on machine learning operators, leaving irregular, heterogeneous, data-movement-heavy database-style operators untested. We introduce DataKernelBench, which translates SQL into validated PyTorch TorchPlan programs and evaluates LLMs that optimize either the core tensor-bounded snippet or the full query in CUDA or Triton through execution-guided repair. Across ten proprietary and open-weight models on TPC-H SF10 with an H100 GPU, the strongest full-query CUDA configuration achieves $2.11\times$ speedup over torch.compile at full pass rate. We find that higher-performing implementations commonly use kernel fusion and execution-strategy changes, stronger models benefit most from full-query specialization, and workload context matters more than hardware context. To handle data larger than GPU memory, we extend TorchPlan with Dask-cuDF for on-demand partition loading on TPC-H SF100 with four H100 GPUs, achieving $2.54\times$ speedup

### [3] [Narcissus: Program Synthesis Using Context-Aware LLM Approximations](https://arxiv.org/abs/2608.25657)
*Tilman Hinnerichs,Sebastijan Dumancic,Neil Yorke-Smith*

Main category: cs.AI

TL;DR: Narcissus 是一个语法引导的枚举式程序合成器，它保留 LLM 候选方案的语法树，并根据上下文评分每个候选展开，同时加入正则化项保证所有语法规则可达，从而在目标语言罕见时仍能高效合成符合语法和规格的程序。


<details>
  <summary>Details</summary>
Motivation: LLM 在编程任务中表现优秀，但当目标语言在训练数据中罕见时，其生成的程序常常破坏语法或无法满足规格。现有的枚举式合成器通过将 LLM 候选近似为规则频率来引导搜索，但这种方法丢失了构造的上下文位置信息，并且在候选错误时会剪除所有遗漏的规则，恰好可能在最需要帮助时失效。

Method: Narcissus 提出将 LLM 的候选方案保留为语法树，并在候选程序的上下文中对每个展开进行评分，判断具有相同周围结构的候选是否以相同方式延续，以及该展开是否重建了候选反复出现的片段。同时引入正则化项保持所有规则可达，使错误的候选只会延迟解决方案而不会隐藏它。

Result: 在五个领域和两种搜索后端上，Narcissus 在每个预算下都优于静态引导方法，并持续超越重新提示 LLM 修复自身方案的方法。它比原始候选快一个数量级到达方案，在 ARC 任务上解决了 40%，而原始候选仅解决 13%，且整个搜索过程无需一次 LLM 调用。

Conclusion: Narcissus 通过保留语法树上下文和规则可达性正则化，有效解决了 LLM 在罕见目标语言下合成程序时引导失效的问题，在无需搜索期间调用 LLM 的情况下实现了显著的性能提升。

Abstract: Large language models (LLMs) excel at programming, but not when the task fixes the target language: prompted with a grammar rare in their training data, their programs usually break the grammar or fail the given specification. Enumerative synthesizers search the space of syntactically correct programs systematically guided by LLMs; the state of the art guides them by approximating LLM proposals into rule frequencies, which loses where each construct belongs and prunes every rule the proposals miss, exactly when the proposals are wrong. We present Narcissus, a synthesizer that keeps the proposals as syntax trees and scores each expansion of a candidate program in its context: does a proposal with the same surrounding structure continue the same way, and does the expansion rebuild a fragment the proposals repeat? A regularization term keeps every rule reachable, so wrong proposals delay the solution but cannot hide it. Across five domains and two search backends, Narcissus beats static guidance at every budget and consistently outperforms re-prompting the LLM to fix its own proposals; it reaches proposal-like programs an order of magnitude sooner and solves $40\%$ of ARC tasks where the raw proposals solve $13\%$, all without a single LLM call during search.

</details>
