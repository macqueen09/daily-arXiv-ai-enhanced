### [1] [Modeling Quantum Computing with $π$-calculus](https://arxiv.org/abs/2609.13156)
*Catalin Toma,Manuel Oriol*

Main category: cs.PL

TL;DR: 该文提出PiQuant框架，将量子程序视为并发程序而非顺序程序，用量子变量通过自身通道广播状态的方式建模，是π-演算的简单扩展。


<details>
  <summary>Details</summary>
Motivation: 量子计算对计算机科学家难以理解，因为其充满缺乏直观意义的数学公式，与常规编程语言（变量、赋值、按值传参）的操作语义相去甚远。

Method: 提出PiQuant框架，扩展π-演算，加入处理量子变量的额外语法与语义；将量子程序建模为并发程序，量子变量通过各自通道公布状态，使用它们的代码读取该状态（并可能使其坍缩）。

Result: 给出了PiQuant的语法与语义定义，提供了从并发视角理解量子程序的理论框架。

Conclusion: 用量子变量通道通信的并发语义，可为量子编程提供更直观的、贴近常规编程的理解方式。

Abstract: Quantum computing is a difficult concept to grasp for computer scientists because it is full of mathematical formulas that have no intuitive meaning related to the problem that the code solves. While these formulae define the way the system behaves, the operational semantics is very far from regular programming languages that reason with variables, assignments, and passing by value the results of computation. This article takes a step back to define a theoretical framework where quantum programs are not treated as sequential programs, but rather as concurrent programs where variables advertise their states through their own channels and code that uses them is reading that state (and possibly collapsing it).
  The PiQuant framework is a simple extension of the $π$-calculus that contains additional syntax and semantics for the handling of quantum variables.

We have demonstrated the adequacy of our API specification for the mutator (client of the garbage collector) by verifying client programs. Our program and our verification are modular so that (1) the API spec is independent of the implementation (e.g., the choice of copying vs. mark-and-sweep, generational-vs-nongenerational) and (2) the specification and verification of components of the implementation (such as the forwarding function) are independent of other components (e.g., design decisions regarding older generations, multiple threads, or "remembered sets" of mutable references).

<details>
  <summary>Details</summary>

As a result, most equality saturation users still manually develop and maintain rulesets.

Enumo's composable operators even facilitate developing new strategies for ruleset inference. Enumo is also easy to extend: two new operators suffice to incorporate large language models into rule inference, where they complement guided search.
  We evaluate Enumo and fast-forwarding across a variety of domains. Compared to state-of-the-art techniques, Enumo can synthesize better rulesets over a diverse set of domains, in some cases matching the effects of manually developed rulesets in systems driven by equality saturation.

### [4] [Opportunistic ZGC: Leveraging Idle Cores for More Effective Concurrent Garbage Collection](https://arxiv.org/abs/2609.15558)
*Jacob Malloy,Michael R. Jantz,Terry Jones*

Main category: cs.PL

TL;DR: 本文提出 OppZGC，一种反馈驱动的 ZGC 调度策略，利用 CPU 空闲时段进行并发回收，动态限制堆内存使用，在几乎不影响吞吐和延迟的前提下，将 DaCapo 基准的最大堆占用降低 61%–90%。


<details>
  <summary>Details</summary>
Motivation: ZGC 虽支持亚毫秒级并发回收，但默认调度保守，倾向把堆增长到最大上限再回收。若最大堆未按实际工作集调优，既浪费内存甚至可能有害；而频繁回收又因同步开销和资源共享拖慢 mutator。

Method: 提出 OppZGC：一种无需逐应用调优、反馈驱动的 ZGC 调度策略，能识别 CPU 核心利用率不足的时段并借机执行并发回收；在 OpenJDK HotSpot 中实现该设计。

Result: 在 DaCapo Chopin 与 SPECjbb 的标准及延迟敏感基准上评估：当 CPU 有足够余量时限制堆使用，避免会显著降低性能的额外回收；DaCapo 最大堆占用平均降低 61%–90%（视配置而定），吞吐和请求延迟相比默认 ZGC 影响极小。

Conclusion: OppZGC 通过反馈驱动调度，在保持低延迟与高吞吐的同时显著减少堆内存占用，实现自动且无需调优的内存约束。

Abstract: Managed language runtimes often provide concurrent garbage collectors so that latency-critical applications with large working sets can keep running while most collection work proceeds in the background. ZGC is a production-quality, generational, concurrent collector in OpenJDK with sub-millisecond pause times. While ZGC is designed to run concurrently, frequent and excessive collections with ZGC can still slow the mutators due to synchronization costs and interference with shared computing resources. Hence, the ZGC scheduler is conservative by default, and in most cases, will grow the heap toward the maximum allowed before scheduling a collection. While this approach minimizes collection effort, it can be wasteful, or even harmful, if the maximum heap size is not well tuned to the actual working set.
  We propose Opportunistic ZGC (OppZGC), a feedback-directed ZGC scheduling policy that constrains the heap dynamically and automatically, without per-application tuning. OppZGC identifies periods when CPU cores are underutilized and leverages them for concurrent collection with ZGC. We describe the design and implementation of OppZGC in OpenJDK's HotSpot Java VM and evaluate it with standard and latency-sensitive benchmarks from DaCapo Chopin and SPECjbb. OppZGC limits heap usage when there is CPU capacity sufficient for additional collections, and avoids scheduling extra collections when they would substantially degrade performance. Overall, it reduces maximum heap usage for our DaCapo benchmarks by between 61% and 90%, on average, depending on configuration, with minimal impact on throughput and request latency compared to default ZGC.

</details>

### [5] [Enforcement of In-Kernel Stateful Security Policies via eBPF](https://arxiv.org/abs/2609.13930)
*Letterio Galletta*

Main category: cs.CR

TL;DR: BPFence：一种内核态运行时验证框架，用带形式语义的策略语言表达事件时序关系，将良类型策略编译为可证明正确的有限状态监控器及eBPF程序。


<details>
  <summary>Details</summary>
Motivation: 多租户系统上的攻击多为多步、依赖历史，恶意性只在执行轨迹中显现。现有方案各有缺陷：内核syscall过滤与经典MAC无状态；eBPF工具用YAML规则，无法表达时序关系且语义仅由实现定义。

Method: BPFence提供带形式语义的策略语言，可表达事件间时序关系；引入类型系统静态区分内核可控事件与仅可观测事件；将每个良类型策略编译为有限的、相对语义可证明正确的状态监控器，再编译为运行于内核的eBPF程序。

Result: 在七个源自真实攻击模式的案例研究上评估，并进行微基准与宏基准测试，表明强制开销可与生产部署兼容。

Conclusion: BPFence满足内核内、有状态、精确语义三项要求，兼顾时序表达与可证明正确性，且开销可接受。

Abstract: Many attacks against workloads running on multi-tenant systems are multi-step and history-dependent: sequences of innocuous operations whose malicious nature emerges only over an execution trace. Defending against them requires security policies that are stateful, are enforced within the kernel, and have a precise semantics. Currently deployed proposals fail on at least one count: kernel's built-in syscall filtering and classical MAC frameworks are stateless, while current eBPF-based tools express their policies through ad hoc YAML rules that cannot capture temporal relations among events, and whose semantics is defined only by the implementation.
  We present BPFence, an in-kernel runtime-verification framework that satisfies the properties above. BPFence provides a policy language with a formal semantics that can express temporal relations among events. It also provides a type system that statically distinguishes events the kernel can control from those it can only observe. Every well-typed policy is compiled into a finite-state monitor proved correct with respect to its semantics, and then into eBPF programs that run inside the kernel. We evaluate BPFence on seven case studies drawn from real-world attack patterns, and on a set of micro- and macro-benchmarks to show that the enforcement overhead remains compatible with production deployment.

### [7] [Reducing Cold-Start Latency in Serverless Applications via Dynamic Slicing](https://arxiv.org/abs/2609.14040)
*Georgios Alexopoulos,Konstantinos Karakatsanis,Nikolaos Alexopoulos,Dimitris Mitropoulos,Thodoris Sotiropoulos*

Main category: cs.DC

TL;DR: PyXtrim通过动态切片技术对Python无服务器应用进行去膨胀，降低冷启动延迟和内存占用。


<details>
  <summary>Details</summary>
Motivation: Python是无服务器应用的主流语言，但其动态特性和大量原生扩展使传统静态去膨胀困难，导致冷启动延迟高。

Method: 将去膨胀建模为动态切片问题，以应用外部可见行为为切片准则，通过跨语言动态依赖引擎追踪Python与原生代码间的数据和控制依赖，识别与操作系统交互的操作。

Abstract: We present PyXtrim, a system that reduces the cold-start latency of serverless applications through debloating. This is more than double the reduction achieved by the state of the art, while debloating each application in minutes.

</details>
