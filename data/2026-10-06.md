*Yusuke Izawa,Junichiro Kadomoto*

Main category: cs.PL

<details>
  <summary>Details</summary>
Motivation: 在无线传感/网状网络、模块化机器人和形态自适应计算机中，模块可在其他模块持续运行并保留本地状态时接入、断开或被替换。旧拓扑下计算出的值（如缓存下一跳）仍留在内存中，但可能不再描述当前拓扑，程序可能向已离开的邻居发送数据而不触发任何运行时错误。

Method: 提出morph-aware computing：应用用repair指定对这类状态进行修正性更新，由编译器决定其运行时机。设计MorphLang，其中repair是紧邻发送、接收和传感器采样等普通分支的Reconfigure分支。实现MorphC，将MorphLang编译到裸机RISC-V，并在每个普通分支前插入guard，使各模块在任何分支看到新拓扑前先修复状态。基于此顺序，MorphC还拒绝目标可能为字面量或repair不总能刷新的值的发送。对代码生成模型在Rocq中证明repair先于后续所有普通分支（任意角色数与拓扑变化数），从而证明send-target检查对核心语言是可靠的。

Result: 在来自7个网络栈的19个MorphLang程序中，移除repair使13个声明repair的程序中有10个的目的有效性变差，且从不改善。在已发布Contiki-NG缺陷的简化复现中，基于回调的版本在384次变化后仍有60次向已离开的父节点发送，而MorphLang版本为0次。微基准测试中guard每循环开销12个周期；在FPGA上，每次提交到首次向新邻居发送的延迟与RTL仿真一致。

Conclusion: morph-aware computing通过将状态修复与应用逻辑的普通分支解耦并强制由编译器安排guard，使拓扑变化后的过期状态在使用前被修正，并可在编译期检查发送目标有效性。形式化证明、多程序实验、实际缺陷复现和硬件测量共同表明该方法有效、开销可接受且与底层实现一致。

A value computed under the old arrangement, such as a cached next hop, stays in memory but may no longer describe the current one, so a program can send to a neighbor that has left without any runtime errors.

Relying on this order, MorphC also rejects sends whose target may be a literal or a value the repair does not always refresh.

In a reduced reproduction of a released Contiki-NG defect, a callback-based version sends to a departed parent after 60 of 384 changes and the MorphLang version after none. The guards cost 12 cycles per loop in a microbenchmark, and on an FPGA the delay from each commit to the first send to the new neighbor matches RTL simulation.
