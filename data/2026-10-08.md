### [1] [Automatically Detecting and Fixing Deadlocks in Go Code with GoDDaR](https://arxiv.org/abs/2610.08962)
*Gustavo Feio,Jorge Coelho,Miguel Flor,João M. Lourenço,António Ravara*

Main category: cs.PL

TL;DR: GoDDaR：静态检测 Go 程序的全局/局部死锁，并自动生成修复建议（diff）。


<details>
  <summary>Details</summary>
Motivation: Go 运行时检测器只能发现执行时出现的全局死锁（所有 goroutine 阻塞），因调度不确定性无法识别仅部分 goroutine 永久阻塞的局部死锁。静态检测局部死锁对可靠并发软件开发至关重要，且现有工具多仅检测而不辅助修复，涉及复杂交织与通信模式推理，难度大。

Method: GoDDaR 将 Go 源码翻译为反映消息传递通信事件与组合模式的中间表示；在该表示上通过符号分析识别局部死锁；再通过变换中间表示消除问题同步模式，从而为原始 Go 源码生成修复建议（以 diff 形式）。

Result: 在来自文献与 git 仓库的代表性死锁基准集上评估，验证了算法正确性并与现有先进方法比较性能。结果表明 GoDDaR 在局部死锁检测上与顶级方法相当，并在自动化死锁修复方面推进了技术水平。

Conclusion: GoDDaR 实现了未观测全局或局部死锁的静态检测与具体修复建议生成，兼具竞争性的检测能力与领先的自动修复能力。

Abstract: The Go programming language provides a lightweight abstraction for concurrent programming through goroutines, which are prone to deadlocks. Go includes a runtime detector that aborts execution when all threads are blocked (a global deadlock). However, due to nondeterministic thread scheduling, this runtime mechanism only detects global deadlocks that manifest during execution and cannot identify partial deadlocks, where a subset of goroutines is permanently blocked while at least one remains runnable. Statically detecting local deadlocks is essential for developing dependable concurrent software.
  While several tools statically detect deadlocks in concurrent programs, few assist developers in fixing them. Detecting and resolving partial deadlocks requires reasoning about complex interleavings and communication patterns, an inherently challenging task.
  In this paper, we present GoDDaR, a tool that detects unobserved global or partial deadlocks in Go programs and suggests concrete fixes. GoDDaR translates Go source code into an intermediate representation reflecting message-passing communication events and composition patterns. Partial deadlocks are identified through symbolic analysis over this representation. To resolve detected deadlocks, our algorithms transform the intermediate representation to eliminate problematic synchronization patterns, allowing GoDDaR to generate fix suggestions for the original Go source code as a diff.
  We evaluate GoDDaR on a benchmark suite of representative deadlock examples from literature and git repositories to validate algorithm correctness and compare performance against the state of the art. Results demonstrate that GoDDaR is competitive with top approaches in partial deadlock detection and advances the state of the art in automated deadlock fixing.

### [2] [When Double Rounding is Correct](https://arxiv.org/abs/2610.09005)
*Brett Saiki,Bill Zorn,Cynthia Richey,Zachary Tatlock*

Main category: cs.PL

TL;DR: 本文提出可精确高效检验的双重舍入正确性判据，基于统一抽象数字格式，并用Lean 4形式化，进而构建MPFX多精度库，实现比MPFR快约6倍、与SoftFloat相当的正确舍入模拟。


<details>
  <summary>Details</summary>
Motivation: 现代ML加速器使用现有数字库不支持的专用数字格式，模拟困难；传统扩展方法为每个操作-格式-舍入模式组合编写专门实现，成本高。双重舍入（高精度计算后重舍入）可复用高精度内核，但其正确性仅在少数情况已知。

Method: 给出跨多种格式和舍入模式下双重舍入正确性的精确、高效可检验刻画；提出统一定点与浮点的抽象数字格式，将双重舍入正确性归约为格式包含关系；在Lean 4中机械化证明；提出格式推断算法，对操作序列上界每表达式的包含格式；实现MPFX多精度数字库。

Result: MPFX正确舍入操作比MPFR快至多11倍（均值6.05倍），与SoftFloat相当（0.46x–1.63x，均值0.94x）；案例研究中用MPFX原语模拟硬件规范的软件版本比SoftFloat快至多13.5倍。

Conclusion: 通过抽象格式与格式包含关系刻画双重舍入正确性，可高效支持多格式正确舍入模拟，显著提升ML加速器硬件模拟性能。

Abstract: Number libraries, which implement number formats and their arithmetic in software, are used to simulate hardware, making hardware behavior reproducible and thus verifiable and easier to design. However, modern machine learning accelerators are difficult to simulate, as they increasingly use specialized number formats that existing number libraries do not support. It is costly to extend these libraries using traditional methods: each combination of operation, format, and rounding mode typically requires a bespoke implementation. An easier way is to double round---compute at higher precision, then re-round---so that one high-precision kernel serves many formats, but double rounding is only known to be correct in select cases.
  We give a precise, efficiently checkable characterization of when double rounding is correct across many formats and rounding modes. Our result rests on a novel abstract number format that unifies fixed- and floating-point representations, reducing the correctness of double rounding to format containment: whether every value of one format is representable in another. We mechanized these results in Lean 4. In addition, we introduce a format inference algorithm that, given a sequence of operations, bounds each expression by a number format guaranteed to contain its result.
  We apply these insights in two ways. First, we present MPFX, a correctly-rounded, multi-precision number library that exploits correct double rounding to efficiently simulate many number formats. MPFX's correctly-rounded operations are up to 11x (mean: 6.05x) faster than MPFR's, and competitive with SoftFloat's---between 0.46x and 1.63x as fast (mean: 0.94x)---at the same precision. Second, in a case study, we implement a software simulation of a hardware specification using both SoftFloat and MPFX's primitives; the MPFX version is up to 13.5x faster.

</details>


### [3] [Modular Responsiveness Verification of Rust Async Runtimes](https://arxiv.org/abs/2610.09198)
*Yanze Li,Ivan Beschastnikh,Alexander J. Summers*

Main category: cs.PL

TL;DR: 该论文提出一种轻量级、模块化的证明技术，用于验证Rust异步运行时的最终进展（liveness）保证。


<details>
  <summary>Details</summary>
Motivation: 异步运行时的正确性至关重要，但验证工作很少。用户最关心的性质是liveness：提交到运行时的任务最终能取得进展。并发且高度优化的库使liveness验证十分困难。

Method: 提出一种轻量级、模块化的证明技术，在基于Rust及其异步模型的简化语言中描述该技术，并将其实现为一组面向Rust的静态分析。

Result: 利用这些静态分析成功验证了多个Rust异步运行时实现中若干关键组件的最终进展性质。

Conclusion: 该模块化证明技术可有效用于验证并发且高度优化的Rust异步运行时的liveness保证。

Abstract: Asynchronous (async) programming is a popular paradigm for managing concurrency. Languages that provide async support typically have a runtime to manage asynchronous executions. These runtimes are critical infrastructure, yet verifying them has received little attention. One reason is that a property that users care most about from an async runtime is a liveness property: tasks submitted to the runtime eventually make progress. Verifying liveness is challenging for libraries that are both concurrent and highly optimized. We present a lightweight and modular proof technique for verifying eventual progression guarantees for Rust async runtimes. We describe this technique in the context of a simple language based on Rust and Rust's async model. We then realize this proof technique as a set of static analyses for Rust and use these to verify eventual progression of several key components of multiple Rust async runtime implementations.

### [4] [Cost-Efficient Theorem Proving via Agent Orchestration in Program Verification](https://arxiv.org/abs/2610.09681)
*Shuangjie Yao,Nikolaus Holzer,Mark Paul Santolucito,Baishakhi Ray,Suman Jana,Dongdong She*

Main category: cs.AI

TL;DR: CoCo-Prover将成本高效的程序证明形式化为双层证明图（声明内AND/OR超图+跨声明引理依赖图）下的元级决策，通过符号化目标选择与智能体路由的行动选择，实现更优的成功率-成本前沿。


<details>
  <summary>Details</summary>
Motivation: 现有证明器一味追求通过率、无视采样/搜索预算，忽略成功-成本权衡；而真实软件常含数百个相互依赖的证明义务，大规模下重要的是经济地证明多少，而非能否证明单个定理。

Method: 基于双层证明图：声明内为AND/OR证明超图，跨声明为引理依赖图。每步回答两问题：选择哪些开放目标（符号化拓扑遍历），以及在这些目标上购买哪些行动（智能体编排的元级决策）。行动选择用智能体路由器，将每次有界专家调用视为单独定价的最优努力计算，把异构专家智能体与配置匹配，随证据累积演化路由规则。

Result: 在Lean 4的五个基准（函数级CLEVER、VERINA、AlgoVeri，仓库级NTP4VC、Vero）上，CoCo-Prover的成功率-成本前沿优于前沿编码智能体和最先进LLM证明器；每个基准均取得最佳求解率，两个基准达100%；相比最强基线配最强LLM成本最多降低30.9%。

Conclusion: CoCo-Prover通过双层证明图与元级成本决策，在程序验证中同时提升求解率并降低成本，为LLM生成代码的可验证性提供了经济高效方案。

Abstract: Program verification establishes software correctness through machine-checkable proofs constructed in theorem provers. It's a guarantee especially valuable for code generated by large language models (LLMs), which is fluent but carries no assurance of correctness. Almost all existing provers, however, pursue pass rates alone at whatever sampling or search budget it takes, and overlook the success-vs-cost frontier; yet real software often carries hundreds of interdependent proof obligations, so what matters at scale is not whether one theorem can be proved, but how many can be proved economically. We introduce CoCo-Prover, which formalizes cost-efficient program proving as metalevel decision-making under cost, grounded on two-level proof graphs: an AND/OR proof hypergraph within each declaration is joined to a lemma-dependency graph across declarations; and at each step, it answers two questions: which open goals to select, and which actions to purchase on these goals. Selection stays symbolic as a topological pass over the proof graphs. Action choice is agent orchestration via metalevel decision-making: an agentic router treats every bounded specialist invocation as a separately priced, best-effort computation, matching heterogeneous specialist agents together with configurations, under evolved routing rules as evidence accumulates. On five program verification benchmarks in Lean 4 including function-level CLEVER, VERINA, and AlgoVeri, and repository-level NTP4VC and Vero, we show that CoCo-Prover achieves a better success-vs-cost frontier than baselines including frontier coding agents and state-of-the-art LLM-based provers: it achieves the best solve rate on every benchmark and up to 100% on two benchmarks. It also reduces cost by up to 30.9% compared to the strongest baseline with the strongest LLM in our evaluation.

</details>

### [5] [Certified Splitting: Decidability and Anchor Supply for Maximal-Munch Tokenization](https://arxiv.org/abs/2610.08854)
*Nicklas Nidhögg*

Main category: cs.FL

TL;DR: 本文提出"认证位置(certified position)"概念——可仅凭词元集判定、标记工作可安全起始的字节位置,并在在线/离线两种判定路径下生成锚点清单。由此导出切分、编辑影响范围、分隔符、审计等系列定理,每一定理附可执行检查。


<details>
  <summary>Details</summary>
Motivation: 分词(tokenization)中何处可安全并行/分段处理缺乏理论依据;需要一种仅依赖词元集、可判定且可验证的"安全起点"概念,来解释切分、编辑传播与审计中的边界行为。

Method: 定义证书为含原点的字节窗口:若窗口末字节所含词元始于此原点,则认证该位置。判定分两条路:对字面量词表用带完整性截止的在线算法;对任意正则词元集用离线"武装运行"验证器。二者在预算下产出锚点清单并对每次拒绝给出见证。继而把锚点正向读入切分、编辑与审计场景并证明相应定理。

Result: 证明:(1)在认证锚点切分并独立扫描可复现顺序分词,无需推测与修正;(2)保可标记性的字节替换仅在两侧未变字节所见证的锚点之间移动边界;(3)长度≤L的词元在p处编辑不影响≤p−L+1的边界;(4)分隔符仅词元起始允许前置切、仅词元结尾允许后置切,故内嵌分隔符错误被拒;并给出锚点无界跨度判定(UTF-8三种情况)与差分审计器(带见证)。

Conclusion: 认证位置为分词提供可判定、可验证的安全切分基础,统一切分、编辑传播、分隔符与差分审计理论;所有定理有可执行检验,测量均可复现,所研究的线程化扫描器在归档语料上依认证锚点切分且边界流逐字节一致。

Abstract: A certificate is a window of bytes with an origin inside it: wherever the window occurs in a completely tokenizable input, the token covering the window's final byte begins at that origin. Decided from the token set alone, a certified position marks where work may soundly begin. This paper decides certification and reads its anchors forward, into cuts, edits and audits. Certification is decided two ways: online with a completeness cutoff for literal vocabularies, and offline through an armed-run verifier for arbitrary regular token sets. Either route, under a declared window budget, yields the anchor inventory, with a witness on each refusal. The consequences are theorems. Cutting an input at certified anchors and scanning the chunks independently reproduces the sequential segmentation, with no speculation and no fixup pass. A byte substitution that keeps the input tokenizable moves boundaries only strictly between the certified anchors witnessed in the unchanged bytes on either side of it. For tokens of length at most L, an edit at p moves no boundary at or below p - L + 1. A delimiter permits a sound cut before it exactly when it sits only token-initial, and one after it exactly when only token-final, so the embedded-delimiter failure is refused. Two instruments follow: the anchor-free span of a finite certified inventory, decided bounded or not with its exact supremum, three for the UTF-8 shape; and a differential auditor deciding whether two token sets place different boundaries on an input both tokenize, with witnesses. Every theorem carries an executable check. Every measurement is a named program's output or arithmetic on such outputs, each program shipped with the paper or pinned by commit in the library it studies; that library's threaded scanner splits the archived campaign corpus at certified anchors, its boundary stream byte-identical throughout.

</details>
