### [1] [DLCB: Ahead-of-Time Compilation for Dynamic Deep Learning](https://arxiv.org/abs/2610.10547)
*Alexander Collins,Bin Fan,Evghenii Gaburov,William Brandon,Sean Lee,Hanfeng Chen,Vinod Grover*

Main category: cs.PL

TL;DR: DLCB是一个嵌入PyTorch的深度学习编译器，采用三级编译策略解决动态张量形状下AOT编译与性能的矛盾。


<details>
  <summary>Details</summary>
Motivation: 深度学习负载中张量形状常无法在编译时完全确定（批次大小、序列长度、空间分辨率变化），造成AOT编译（性能高但需静态形状）与JIT编译（支持动态形状但有运行时开销）之间的根本矛盾。

Method: 统一三级编译策略：1) 全静态形状→AOT生成静态CUDA C++内核；2) 秩静态但维度动态→AOT生成以维度为参数的内核，一次编译多次执行；3) 秩未知→回退JIT。对动态形状AOT，从输入程序构建形状约束系统，用求解器化简为固定约束（硬编码常量）或未解析约束（作为启动时内核参数，并配合解释型host代码验证约束并计算传参）。

Result: 通过形状约束求解与自动形状泛化pass，实现了对受支持PyTorch程序子集的动态形状AOT编译，编译器与运行时嵌入PyTorch中。

Conclusion: DLCB在静态与动态形状之间提供折中方案，兼顾AOT峰值性能与动态形状灵活性，并集成于PyTorch。

Abstract: Deep learning workloads are increasingly deployed in settings where tensor shapes are not fully known at compile time. Batch sizes vary across requests, sequence lengths differ between inputs, and model architectures admit a range of spatial resolutions. This dynamism creates a fundamental tension: ahead-of-time compiled GPU kernels deliver peak performance but traditionally require fully static tensor shapes, while just-in-time compilation supports dynamic shapes at the cost of runtime compilation overhead.
  We present DLCB (Deep Learning Compiler Backend), a deep learning compiler that resolves this tension through a unified three-tier compilation strategy. For programs with fully static tensor shapes, DLCB generates static CUDA C++ kernels ahead of time. For programs whose tensor rank is statically known but whose dimension sizes are dynamic, DLCB generates AOT kernels parameterized by those dimensions, compiling once and executing across a range of shapes. For programs with tensors of unknown rank, DLCB falls back to JIT compilation at runtime.
  For AOT compilation with dynamic shape tensors, our approach builds a system of shape constraints from the input program, and uses a solver to reduce these to either a) fixed constraints that produce hard-coded constants in the generated kernel; b) unresolved constraints which become kernel parameters passed at launch time, along with interpreted host code to check that the constraint holds for a given set of inputs and to compute the values to pass.
  Our compiler and runtime are embedded in PyTorch, and use an automatic shape generalization pass to enable AOT compilation with dynamic shapes for supported subsets of PyTorch programs

### [2] [Bayes Rule for Conditioning Probabilistic Programs](https://arxiv.org/abs/2610.10792)
*Feras A. Saad*

Main category: cs.PL

TL;DR: 该论文针对概率程序中的零概率观测条件化问题，指出现有"软条件化"和"邻域极限"方法在测度论上不完备，提出基于几何测度论的分解语义，给出可用的贝叶斯规则表示及可靠的推断结果。


<details>
  <summary>Details</summary>
Motivation: 概率程序继承自概率论的一个核心理论难题是：当观测事件概率为零时如何进行条件化。现有语言多用计算规则处理，虽对部分问题有效，但统计上不可靠、不完备。

Method: 首先论证基于"软条件化"和"邻域极限"的技术存在测度论语义问题，会产生不符合严格统计推理的推断结果；随后借助几何测度论工具，为概率程序轨迹构建一种新的、基于分解的条件语义。

Result: 该理论给出了条件分布的显式贝叶斯规则表示，可直接兼容需要未归一化后验密度的主流概率推断算法；并能处理带循环、分支、离散/连续/混合型分布、流形上观测、可微结构及多种实际建模模式的概率模型。

Conclusion: 论文提出了一个原则性的条件化语义框架，能够对概率程序进行统计可靠的条件化，并支持广泛的模型结构与推断算法。

Abstract: Probabilistic programs provide a rigorous programming-language foundation for expressing rich probabilistic models and offer language-level support for solving challenging statistical inference problems. A key theoretical challenge that probabilistic programs inherit from probability theory is conditioning a probability distribution on an observation that has probability zero. Many languages address this challenge by using computational rules for conditioning that may work well for some problems but are statistically unsound for others.
  This article introduces a principled mathematical approach for conditioning probabilistic programs. We first show that existing techniques based on "soft conditioning" and "neighborhood limits" exhibit semantic issues from the perspective of measure theory and produce inference results that disagree with sound statistical reasoning. By leveraging tools from geometric measure theory, we construct a novel disintegration-based semantics for probabilistic program traces that enables sound conditioning. The theory delivers an explicit Bayes rule representation of the conditional distribution, which is directly compatible with widely used probabilistic inference algorithms that require access to unnormalized posterior densities. Our Bayes rule handles probabilistic models with loops, branches, discrete, continuous, and mixed-type distributions, observations on manifolds, differentiable structure, and additional modeling motifs that arise in practice.

### [3] [Quantitative Verification of Infinite-State Networks](https://arxiv.org/abs/2610.11991)
*Dhruv Nevatia,David Basin*

Main category: cs.FL

TL;DR: 本文提出针对加权下推系统无环网络的定量验证框架，核心是"泵送半环"类及精确饱和算法。


<details>
  <summary>Details</summary>
Motivation: 现有下推系统网络的可判定性结果基本是定性的，无法处理代价、延迟、可靠性等定量行为，因为定量分析需要同时跟踪轨迹与权重，递归、无界局部状态与定量行为结合带来了新困难。

Method: 定义"泵送半环"（pumping semirings）：其上嵌套循环泵送积累的权重可坍缩为闭式，域无法计数迭代。据此提出终止的饱和算法精确计算定量可达性，依赖两个概念：段树代数（运行的组合式表示）与热扩展（符号化分离加速权重以保持加速精确性）。

Result: 该框架支持具有无限升链的域（如arctic半环、下闭语言）；可用于统一计算上下文无关语言的上闭包与下闭包；并可将算法提升至"薄"泵送半环上的无环网络，首次实现下推系统网络的定量安全性与可达性分析。

Conclusion: 为加权下推系统及其网络提供了精确的定量验证方法，突破了递归网络有限摘要化中精确坍缩的长期难题。

Abstract: Many network protocols and distributed systems combine recursion, unbounded local state, and quantitative behaviour such as cost, latency, or reliability. Existing decidability results for networks of pushdown systems are largely qualitative, and do not extend to quantitative analyses, which must jointly track traces and weights.
  We present a framework for the quantitative verification of acyclic networks of weighted pushdown systems. Finitely summarising a recursive network component requires collapsing the infinite family of runs obtained by pumping its nested loops, and doing so \emph{exactly}, rather than by over-approximation, is a standing difficulty. We give a class of weight domains where this is possible: pumping semirings, those in which the weights accumulated by such a family collapse to a closed form; informally, the domain must be unable to count iterations. The class admits domains with infinite ascending chains, such as the arctic semiring and downward-closed languages. Over these, we give a terminating saturation algorithm computing quantitative reachability exactly, resting on two ideas: segment tree algebras, a compositional representation of runs, and thermal extensions, which symbolically separate accelerated weights so that further acceleration remains exact. We use this to compute upward and downward closures of context-free languages uniformly, and to lift the algorithm to acyclic networks over "thin" pumping semirings, yielding the first quantitative safety and reachability analyses for networks of pushdown systems.

### [4] [Code Understanding is a Bottleneck for Coding Agents](https://arxiv.org/abs/2610.10610)
*Nishant Balepur,Kiran Tomlinson,Tobias Schnabel*

Main category: cs.SE

TL;DR: CABRA：一种从零构建、通过调用图变换和任务规模参数控制难度的编码能力评估框架，用于严谨评测编程智能体。


<details>
  <summary>Details</summary>
Motivation: SWE-bench等仓库基准常假设"编辑的代码行数"能预测任务难度，但这些数据集对代码与任务类型控制不足，难以判断真正驱动智能体错误的究竟是哪些能力。

Method: 从零构建任务，以调用图变换为基础，通过任务规模参数在四个维度上扩展难度：函数遍历、搜索、运行时解析、指令遵循；在6,840个任务上测试8个LLM和6个编程智能体。

Result: 1) 随任务规模增大LLM准确率下降，但智能体通过把工作卸载给工具（如grep）仍近乎完美；2) 更大的CABRA任务引发更多工具调用，且在SWE-bench Verified上工具调用次数比编辑行数更能预测智能体准确率；3) 扩展到跨两个类分析分歧逻辑的强理解任务时，智能体准确率终于下降。

Conclusion: 主张采用CABRA这类合成评估来揭示被工具（如大海捞针）平凡化的LLM弱点，以及编程智能体仍感困难的编辑之外的能力（如理解），并将SWE-bench式任务与受控诊断配对使用。

Abstract: Repository benchmarks (e.g., SWE-bench) for coding agents often assume that lines of code edited can predict task difficulty, but such datasets' poor control over code and task types makes it hard to know which abilities truly drive agent errors. We present CABRA: a Coding Ability Blueprint for Rigorous Agent evaluation. CABRA builds tasks from scratch as call graph transformations and scales difficulty via a task size parameter on four axes: function traversal, search, runtime resolution, and instruction following. We run eight LLMs and six coding agents on 6,840 CABRA tasks to show: 1) LLM accuracy falls as task size~grows, but agents stay near-perfect by offloading work to tools (e.g., grep); 2) Larger CABRA tasks elicit more tool calls for reading and analysis, while a separate study on SWE-bench Verified shows these tool call counts predict agents' accuracy better than lines of code edited, suggesting task difficulty for agents can lie in understanding code to edit, not just in making edits; 3) Extending CABRA to an intense understanding task where models analyze divergent logic across two classes backs this finding, as agent accuracy finally falls. More broadly, we argue for synthetic evaluations like CABRA to unmask LLM weaknesses trivialized by tools (e.g., needle-in-a-haystack) and abilities beyond just editing (e.g., understanding) that coding agents still find difficult, pairing SWE-bench-style tasks with controlled diagnosis.

</details>


### [5] [Can LLMs Simulate Novice Programmers' Misconceptions?](https://arxiv.org/abs/2610.10656)
*Batuhan Yeltekin,Daniel Bauer*

Main category: cs.SE

TL;DR: 评估13个LLM在代码追踪问题上生成、解决、模拟和诊断新手编程误解的能力，发现前沿模型表现可靠，小模型（≤14B）难以处理动态执行，代码微调模型在误解模拟中会退回到正确执行，且True/False格式的误解诊断显著易于开放式生成。


<details>
  <summary>Details</summary>
Motivation: 探究LLM能否胜任编程教育中与新手误解相关的多方面任务，识别不同规模与类型模型的能力边界。

Method: 对13个LLM在代码追踪问题上进行四类任务测试：生成、求解、模拟和诊断新手编程误解。

Result: 前沿模型可靠完成这些任务；小模型（≤14B）在动态执行上表现挣扎；代码微调模型在误解模拟中回退到正确执行；True/False格式的误解诊断明显比开放式生成任务更容易。

Conclusion: LLM在编程误解相关任务上能力不均，模型规模与训练方式影响显著，诊断任务的格式对难度有重要影响。

Abstract: We evaluate 13 LLMs on generating, solving, simulating, and diagnosing novice programming misconceptions on code-tracing problems. While frontier models reliably perform these tasks, small models ($\le$14B) struggle with dynamic execution. Notably, code-tuned models fail during misconception simulation by reverting to correct execution. Finally, misconception diagnosis is significantly easier in True/False formats than in open-ended generation tasks.

</details>
