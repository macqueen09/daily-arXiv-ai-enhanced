### [2] [Coexponential Exploration in the Clef Programming Language](https://arxiv.org/abs/2610.12911)
*Houston Haynes*

Main category: cs.PL

TL;DR: Clef 语言的编译器通过跟踪状态所有权、等待计算与请求依赖，以"余指数(coexponential)"模型刻画有状态服务及其客户端池。定界续延保留每次交互所需的计算与资源，使编译器能在下降到多种硬件目标时验证并保持服务组合的正确性。


<details>
  <summary>Details</summary>
Motivation: 现有并发/服务编程语言难以在编译期同时保证状态所有权、请求依赖、服务组合的正确性，并保持一致地落实到异构硬件。作者希望在 Clef 的设计中统一刻画有状态服务与客户端池，让编译器自动携带正确组合所需的条件。

Method: 1) 用余指数服务器(初始/服务/最终规则)刻画有限 actor 状态转移与状态服务/客户端池；2) 用单次使用续延帧的操作语义关联 actor 调度；3) 证明状态所有权与应答保全，给出有限通信摘要分析，并从所需条件中排除循环等待；4) 得出"改变服务顺序仍保持状态与应答"的充分条件；5) 通过程序语义图(PSG)在编译中保留上述事实，用可复用证明项验证所有权与通信接口；6) BAREWire 实现将消息语义与跨端点无装箱表示相连；7) 借助 Urschel 消除-增长界为求解器服务提供定量前提，使其精度与失败预算与协议契约组合。

Result: 证明了状态所有权与应答保全；给出有限通信摘要分析与循环等待排除条件；识别出服务顺序改变仍保状态与应答的情形；在 PSG 中于编译全程保留这些事实；分布式 worker 示例在挂起、乱序应答与边界转换下保持请求标识；求解器服务的精度与失败预算可与协议契约组合。

Conclusion: 该设计将自动结构分析、可复用证明项与原生实现相连接：协议决定可允许的交互，续延暴露其存储需求，保留的依赖支持差分编译。开发者可编写普通的有状态服务，编译器则为其跨执行目标的正确组合携带所需条件。

Abstract: Clef was created as a concurrent programming language whose compiler tracks state ownership, waiting computations and request dependencies. We develop a coexponential account of stateful services and their client pools within this design. Delimited continuations retain the computation and resources needed to complete each interaction. These structures give our compiler premises for verifying service composition and preserving it through native lowering to multiple hardware targets.
  We connect finite actor state transitions to the initial, service and final rules of a coexponential server. A separate operational account relates actor dispatch to single-use continuation frames. We prove state-ownership and reply preservation for that translation, give a finite communication-summary analysis, and circular-wait exclusion from the conditions needed. A further result identifies when changing service order preserves both state and replies.
  Our Program Semantic Graph retains these facts through compilation. We are researching reusable proofs to confirm the ownership and communication interfaces, while our BAREWire implementation connects message meaning to its unboxed representation across respective endpoints. A distributed worker example preserves request identity across suspension, reordered replies and boundary conversion. Urschel's elimination-growth bounds supply quantitative premises for a solver service, whose accuracy and failure budget compose with the protocol contract.
  The design we envision connects automatic structural analysis, reusable proof terms and native realization. Protocols determine the admissible interactions, continuations expose their storage requirements, and retained dependencies support differential compilation. Developers can express ordinary stateful services while the compiler carries the conditions for their correct composition across execution targets.

### [3] [A Simplified Layout Algebra for GPU Kernels](https://arxiv.org/abs/2610.13679)
*Nan An,Xiaotian Zhou*

Main category: cs.PL

TL;DR: 本文提出一种改进的 layout 代数，通过显式标注空间的类型（逻辑、物理、线程-值）来消除 CuTe 原有 layout 代数中复杂的可采纳性条件，并用 OCaml 实现、Rocq 验证。


<details>
  <summary>Details</summary>
Motivation: NVIDIA CuTe 的 layout 代数虽用于描述张量 tile 到线程和内存的映射，但其核心操作（composition、complement、division、product）需满足至少六个相互作用的可采纳性条件。作者认为这种复杂性来自表示方式的选择，而非问题领域本身的固有性质。

Method: 1. 定义带空间标注的 layout：输入输出空间分为逻辑、物理、线程-值三类；逻辑/线程-值空间的 layout 必须是从 N 个坐标到 [0,N) 的双射；物理空间 layout 必须无别名，仅允许广播并显式标记。2. 组合 f 与 g 只需 f 的值域恰为 g 的展平坐标集，索引运算可朴素发出（先算 f，再按除法/取模拆分，再应用 g）；若可化简，则取最粗形式并发射。3. 将线程/warp 切片建模为 restriction，restricted layout 不再可组合。

Result: 在该代数中复现了 CuTe 的 composition、complement、division 等操作；用 OCaml 实现并重新推导 CuTe 的 atoms 与使用模式；决策过程在 Rocq 中证明正确。

Conclusion: CuTe layout 代数的复杂性源于表示选择而非领域本质；通过显式空间标注和 bijection/alias-free 约束，可在保持表达力的同时简化合成规则，并提供实现与形式化验证。

Abstract: The layout algebra behind NVIDIA's CuTe library describes how tensor tiles map onto threads and memory. A layout is a shape with a stride for each entry, so a coordinate's address is the sum of its indices times their strides. As formalized by Shah and by Cecka, its central operations (e.g., composition, complement, division, product) are guarded by at least six interacting admissibility conditions. We show that this complexity is an artifact of a representational choice, not of the domain.
  We present a layout algebra in which every layout names the space its inputs and outputs live in: logical, physical, or thread-value indices. A layout into logical or thread-value space must be a bijection from its $N$ coordinates onto $[0,N)$. A layout into physical space must be alias-free: distinct coordinates land on distinct addresses, except under broadcast, where many threads read one value on purpose and the layout must mark where. Nothing maps out of a physical index.
  Composing $f$ with $g$ requires only that $f$'s range be exactly $g$'s flattened coordinate set. The index arithmetic can always be emitted naively: compute $f$, split the result by division and remainder into $g$'s coordinates, and apply $g$. Often the composite simplifies to a layout; we show that when it does, there is a coarsest such form, whose digits every other one refines, and we emit that.
  A warp's or thread's slice is a \emph{restriction}. A restricted layout is no longer composable, which forces the user to settle the whole view of a tile before taking slices.
  We validate the algebra by reproducing within it CuTe's operations, such as composition, complement, and division. We implement it in OCaml and use the implementation to rederive CuTe's atoms and usage patterns. The decision procedure is proved correct in Rocq.

</details>

### [4] [VortexSynth: Profile-guided benchmark reconstruction for GPU architecture research](https://arxiv.org/abs/2610.12661)
*Huanzhi Pu,Chulhyung Park,Chihyo Ahn,Ramyad Hadidi,Hyesoon Kim*

Main category: cs.AR

TL;DR: VortexSynth：利用profile引导的基准重构，从参考工作负载自动构建可在研究型GPU架构上运行的基准。


<details>
  <summary>Details</summary>
Motivation: GPU架构研究需要代表性基准，但厂商定制的库内核多为闭源或依赖目标架构不支持的编程模型，迁移现有内核需大量手工适配与验证，因此需要自动化的工作负载迁移方法。

Method: 通过profiling选取热点内核，在目标编程语言中合成实现，验证输出等价性；用翻译后的代理实现测量profile差异，将profile签名差距反馈给智能体进行迭代优化。

Result: 在开放ISA的GPGPU平台Vortex上、以机器人为应用领域评估，所有活跃内核对均通过输出等价性检查；案例研究表明迭代优化能缩小profile距离。

Conclusion: VortexSynth实现了从参考工作负载到目标架构的自动化基准重构与验证，可支持研究型GPU架构的基准评测。

Abstract: GPU architecture research requires representative benchmarks that can execute on new designs. However, many vendor-tailored workloads and library kernels cannot run directly on research architectures because their implementations are closed-source or rely on programming models unsupported by the target architecture. Migrating existing kernels requires manual effort to adapt their implementations and validate their behavior. This creates a need to automate workload migration to target platforms.
  We present VortexSynth, a framework that uses profile-guided benchmark reconstruction to construct GPU benchmarks from reference workloads. Our workflow selects hot kernels through profiling, synthesizes implementations in the target programming language, verifies output equivalence, and measures profile differences using a translated proxy implementation. The resulting profile signature gap is supplied to an agent for iterative refinement. We evaluate the method on Vortex, an open-ISA GPGPU, using robotics as the application domain. All active kernel pairs pass both output-equivalence checks, and the case studies show that iterative refinement can reduce profile distance.

</details>
