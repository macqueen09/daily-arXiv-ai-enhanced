### [1] [Recursive Formation and First-Class Reuse of Compositional Capabilities](https://arxiv.org/abs/2610.19414)
*Hang Lin*

Main category: cs.PL

TL;DR: 提出FormCraft框架，将习得操作作为可递归组合、直接调用、选择性保留的一等能力，通过领域特定验证存入持久库。


<details>
  <summary>Details</summary>
Motivation: 使习得操作成为可复用的一等能力，并支持递归组合与持久化，同时区分能力良构性与公共可调用性，避免重新推导历史。

Method: 分离能力良构性/公共可调用性与持久存储准入；保留形成溯源与操作身份；形式化统一能力空间上的递归组合闭包。

Result: 在连续、离散、命题和序列域实验中展示了实例无关复用、独立检查、持久化获取，以及一等暴露下复用搜索工作减少。

Conclusion: FormCraft支持习得能力的递归组合与持久复用，无需重新形成历史推导，并降低复用搜索成本。

Abstract: We introduce FormCraft, a framework for representing acquired operations as first-class capabilities that can be recursively composed, directly invoked, and selectively retained in a persistent library through domain-specific verification. The framework separates capability well-formedness and public callability from later admission to persistent storage while preserving formation provenance and operational identity. We formalize recursive compositional closure over a uniform capability space and show that formed composites can be reused through the same public interface without re-forming their historical derivation. Experiments across continuous, discrete, propositional, and sequence domains demonstrate instance-independent reuse, independent checking, persistent acquisition, and reduced reuse-time search work under first-class exposure.

### [2] [Verifying deployed bytecode against executable EVM semantics, with exact gas and no added axioms](https://arxiv.org/abs/2610.19764)
*Seulkee Baek*

Main category: cs.PL

TL;DR: Blanc 是基于 Lean 4 的以太坊字节码验证栈，配合可执行 EVM 语义 Jaune，直接验证主网部署的原始运行时字节码，无需信任编译器，并用 8 个真实合约（EIP-7002、Uniswap V2、WETH9、Curve 等）证明安全性、功能正确性及 gas 精确性。


<details>
  <summary>Details</summary>
Motivation: 以太坊中许多关键代码是不可变字节码（未验证编译器的产物或作为合约运行的协议逻辑），难以直接验证。现有方法通常依赖对生成工具的信任或简化执行环境，本文希望在不信任编译来源、不简化机器、仅用 Lean 自身公理的前提下，直接验证这些字节码。

Method: 提出 Blanc —— Lean 4 验证栈，通过内核检查的证书读取固定运行时字节；形式化并实现可执行 EVM 与区块处理语义 Jaune，该语义通过 Ethereum fixture v20.0.2 中涉及 2025 年 5 月后主网分叉的 34,205 个区块链测试用例；对 2017–2026 年间部署、来自 7 个编译器版本和 1 个汇编器的 8 个产物进行验证。

Result: 对 EIP-7002 证明：区块末尾调用无论存储如何都成功，且每块提款请求恰好是最早的待处理提交；对 Uniswap V2 pair 证明存储正确表示模型、流动性账本平衡、按份额几何平均储备仅因协议费下降；对 WETH9 证明在特定 gas 条件下提款可活跃；对 2023 年 Curve 锁漏洞字节码，Jaune 从部署起执行出重入漏洞，而对固定编译器字节码证明锁可排除重入。

Conclusion: 证明了可直接对真实以太坊字节码进行严格、无额外公理的验证，覆盖协议逻辑与经济安全性质；AI 代理在一位作者指导下、基于现有技术栈于 15 天内完成全部证明，展示该方法在真实部署合约上的可行性与可扩展性。

Abstract: Much of Ethereum's most consequential code is immutable bytecode: old output of unverified compilers, and protocol logic run as contract code. We show that such bytecode can be verified as it is, without trusting what produced it, without simplifying the machine it runs on, and with no axioms beyond Lean's own. Blanc, a Lean 4 verification stack, reads fixed runtime bytes via kernel-checked certificates and states every theorem against Jaune, an executable semantics of the EVM and block processing that passes all 34,205 blockchain-test cases of Ethereum's fixture release v20.0.2 that involve only forks that have governed mainnet since May 2025. Eight artifacts, deployed from 2017 to 2026, come from seven compiler versions and an assembler. For the EIP-7002 contract, we prove that the end-of-block call to it, whose failure would invalidate the block, succeeds whatever its storage holds, and that each block's withdrawal requests are exactly the oldest pending submissions; mainnet met these theorems' starting premises when Prague began. For a Uniswap V2 pair, we prove that after any valid history whose hashed slots stay apart, from any checkpoint representing its Solidity model's state, the storage represents that model replayed over exactly the committed calls, a balanced liquidity ledger stays balanced, and, under a premise on token answers, geometric-mean reserves per share fall only through the protocol fee. Exact gas makes liveness provable: a tracked WETH9 holder without code can withdraw by a transaction whose gas has a closed form, matching all 3,748 comparable mainnet receipts of its shape in 30,000 blocks. On Curve pool bytes compiled with the lock bug exploited in 2023, Jaune executes such a reentrancy from deployment; for bytes from a fixed compiler, we prove the lock excludes it. AI agents wrote the proofs in fifteen days under one author's direction, atop an existing stack.

### [3] [Typechecking without Minimum Types: Finite Bases and Backward Checking for $F_{<:}^{\top}$](https://arxiv.org/abs/2610.20356)
*Mingkun Xiao,Yixuan Sun*

Main category: cs.PL

TL;DR: 论文证明System F_{<:}^{⊤}在任意显式标注术语下的类型检查可判定，并给出两种全函数实现及复杂度界。


<details>
  <summary>Details</summary>
Motivation: 系统F_{<:}^{⊤}子类型可判定但缺乏最小类型，需要处理类型抽象与量化子类型之间的上下文不匹配问题，从而判定类型检查。

Method: 构造保持所需子类型比较的有限覆盖，得到组合式有限类型基；再由矩形化类型族设计反向检查器，通过有限逆族在类型替换下传播目标，并恢复界遗忘。

Result: 给出两种与原类型判定等价的全函数Rocq类型检查过程；符号字RAM实现具有四次最坏-case工作量界；并用独立OCaml原型测量族表示与比较存储大小。

Conclusion: 类型检查在显式标注与无限制subsumption下可判定，所提覆盖与逆族框架同时支持声明式与算法式实现，验证了可行性与复杂度。

Abstract: System $F_{<:}^{\top}$ has decidable subtyping but lacks minimum types. We prove that typechecking is decidable for arbitrary explicitly annotated terms with unrestricted subsumption. The difficulty is that type abstraction uses a variable's declared bound to type its body, while quantified subtyping forgets that bound. We construct finite covers that preserve all required subtype comparisons across this change of context. These covers yield a compositional finite typing basis and a decision procedure.
  We then derive a backward checker that propagates acceptable targets without constructing the complete typing basis. Rectangularity of typing families gives a uniform elimination domain while retaining every result type, even when the canonical type is not least. Finite inverse families transport targets through type substitution. The same inverse specification recovers bound forgetting and yields finite type-avoidance families. Both typechecking procedures are total Rocq functions proved equivalent to the original typing judgment. For a separate symbolic word-RAM realization, we prove a quartic worst-case work bound. We measure family representation sizes and comparison storage in independent OCaml prototypes on synthetic checking judgments.

</details>

### [4] [MolLean: A Process-Verifiable Language for Chemical Reasoning](https://arxiv.org/abs/2610.20459)
*Jiatong Li,Yatao Bian*

Main category: cs.CL

TL;DR: 提出MolLean，一种以显式分子状态为基础、可过程验证的化学推理语言，并配套MolLean-MCP状态化工具接口，在12项任务上优于直接思维链。


<details>
  <summary>Details</summary>
Motivation: 化学思维链可能包含虚构的结构和性质声称，缺乏可验证性，需要将化学推理建立在显式、可检查的分子状态之上。

Method: 设计MolLean语言：基于Lean的分层内核检查分子读数上的状态转换与断言（从原子图编辑到化合物转换）；类型化见证协议区分原生结构检查与外部测量。提出MolLean-MCP状态化工具接口，在生成中暴露转换、检查与读数，使模型获得反馈决定下一步，被拒动作不改变状态。支持单遍轨迹执行、全轨迹精炼与交互式推理三种模式。

Result: 在8,800个匹配样例、覆盖分子生成/编辑/优化/反应共12项任务上评估。Qwen3.6-27B下，全轨迹精炼在全部12项任务上优于直接思维链；MolLean-MCP以逐步验证反馈补充全轨迹精炼，在反应任务上表现更佳。

Conclusion: 结果确立了可执行的化学推理基础，使显式化学承诺可被检查与修正，而不再仅停留于自由形式解释中。

Abstract: Chemical chain-of-thought can contain hallucinated structural and property claims. We thereby introduce MolLean, a process-verifiable language that grounds chemical reasoning in an explicit molecular state. A layered Lean-based kernel checks state transitions and assertions over molecular readouts, from primitive graph edits to compound transformations. Meanwhile, a typed witness protocol separates native structural checks from externally supplied measurements. We further introduce MolLean-MCP, a stateful tool interface that exposes these transitions, checks, and readouts during generation: the model receives feedback to decide its next action, and rejected actions leave the state unchanged. MolLean supports one-pass trace execution, whole-trace refinement, and interactive reasoning through MolLean-MCP. We evaluate these three modes with direct chain-of-thought on 8,800 matched examples across 12 tasks spanning molecular generation, editing, optimization, and reactions. With Qwen3.6-27B, whole-trace refinement outperforms direct chain-of-thought on all 12 tasks. MolLean-MCP complements whole-trace refinement with stepwise verification feedback, reaching better performance in reaction tasks. Together, these results highlight an executable foundation for chemical reasoning, in which explicit chemical commitments can be checked and revised rather than remaining solely in free-form explanations.

</details>

### [5] [LLMs program using Reusable and Composable Abstract Representations](https://arxiv.org/abs/2610.19238)
*Casper L. Christensen,Kyle J. Ray,Dmitry Manning-Coe,Adam Shai,Paul Riechers*

Main category: cs.LG

TL;DR: LLM激活中存在可复用、可组合的代码抽象表征，独立编码函数、编程语言和实现策略，支持灵活的代码生成控制。


<details>
  <summary>Details</summary>
Motivation: 同一计算可用不同语言与实现策略表达，探究LLM是否捕获这一跨语言/跨实现的共享抽象结构。

Method: 分析LLM生成代码时的激活表征；用激活引导（activation steering）独立操控函数、语言与实现策略；跨语言微调迁移实验；在合成设定下训练最小Transformer模型。

Result: 抽象表征出现在中间层，可跨语言复用；语言/函数/策略可独立操控并可组合控制生成（即使提示无相关信息）；单语言微调可迁移到其他语言；合成模型中Transformer学到可灵活复用的表征。

Conclusion: LLM在代码生成中学习到共享、可复用、可组合的抽象表征，这解释了其泛化与跨语言迁移能力。

Abstract: When writing code, the same computation can be expressed in different programming languages and through different implementation strategies. We show that the activations of LLMs capture this shared structure in reusable and composable abstract representations when they generate code. These representations emerge in the middle layers, are reusable across programming languages, and afford the model an impressive amount of generalization ability when generating code under various interventions. Using activation steering, we show that function, programming language, and implementation strategy can be independently manipulated. The independent interventions on language and function can be flexibly composed to control code generation, even in cases when the prompt contains no information about language and function. We additionally find that finetuning on examples of arbitrarily defined functions in one programming language transfers to other languages, consistent with the models reusing abstract features of code generation that are shared across different examples. Finally, to study how such abstract representations come to be, we implement a minimal model of shared, reusable, and composable structure in a synthetic setting, and show that transformers trained on such data learn representations that reuse these parts flexibly across contexts.

</details>
