### [1] [Arbitrary Functors as Modalities in a Linear Calculus](https://arxiv.org/abs/2610.23023)
*Jean-Philippe Bernardy,Andreas Abel*

Main category: cs.PL

TL;DR: 该论文将线性λ演算中的模态解释为monoidal闭范畴中的自函子，支持不分配于积的函子（包括(co)monad）以及任意自然变换作为模态间转换，给出泛型范畴语义并特化为可靠且完备的资源语义，据此推导NBE，并在Agda中形式化。


<details>
  <summary>Details</summary>
Motivation: 为未来带模态的编程语言奠定基础：现有模态解释通常要求函子对积分配，限制了对(co)monad等模态的建模能力。

Method: 在线性λ演算中把模态视为monoidal闭范畴中的自函子（允许不分配于积），以任意自然变换作为模态转换；先建立泛型范畴语义，再特化为资源语义，并用其导出normalisation by evaluation，辅以Agda机械化验证。

Result: 得到泛型范畴语义及一个可靠且完备的资源语义；由资源语义导出NBE；并给出若干模型应用示例。

Conclusion: 不要求模态函子分配于积的范畴语义框架可行，可统一处理(co)monad与模态转换，并支撑NBE与资源分析，为模态编程语言提供理论基础。

Abstract: We study modalities in the linear lambda calculus, by interpreting them as endofunctors in monoidal closed categories. We support functors that do not distribute over products, including (co)monads. We also support arbitrary natural transformations as conversion between modalities. We provide a generic categorical semantics, which we then specialise to a sound and complete resource semantics. We use this resource semantics to derive normalisation by evaluation. Along the way, we describe several applications of such models. This work aims at providing a foundation for future programming languages with modalities. The paper is backed by a mechanisation in Agda.

### [2] [A Taxonomy of Predicate Transformer Monads for Specifying Monadic Programs](https://arxiv.org/abs/2610.23604)
*Abigail Pribisova,Yao Li,Catalin Hritcu,Cezar-Constantin Andrici,Kenji Maillard,Exequiel Rivas*

Main category: cs.PL

TL;DR: 本文引入首个最强后条件（strongest postcondition）单子，覆盖天使/恶魔非确定性及部分/完全非终止的所有组合，并用箭头（arrow）变换器替代单子变换器以支持状态副作用，最终分类并关联弱前置与强后置单子体系。


<details>
  <summary>Details</summary>
Motivation: 现有验证框架基于弱前置条件谓词变换器单子，但描述带非确定性与非终止的单子计算时，缺乏对应的最强后条件单子；且将基础单子扩展状态副作用时，单子变换器无法得到预期单子。

Method: 引入覆盖天使/恶魔非确定性×部分/完全非终止四种组合的最强后条件单子；将其推广为箭头并用箭头变换器加入可变状态；给出弱前置/强后置单子的分类学；在谓词变换器层面证明欠近似/过近似三元组关系的已有结论；用谓词变换器单子定义欠/过近似三元组及Dijkstra单子。

Result: 建立了弱前置与强后置单子的完整分类（基础版及带状态版），证明基于谓词变换器的欠/过近似三元组关系在谓词变换器本身上已成立，并用该单子定义了欠/过近似三元组和（在可行时）Dijkstra单子，最后关联两种规格风格。

Conclusion: 最强后条件单子（经箭头推广）与弱前置条件单子构成互补且可关联的规格体系，为带非确定性、非终止与状态的单子程序提供统一的欠/过近似验证基础。

Abstract: Monads of weakest precondition predicate transformers are the foundation of several verification frameworks for monadic programs. For specifying monadic computations with nondeterminism and nontermination, in addition to weakest preconditions, we introduce the first strongest postcondition monads covering all combinations of angelic or demonic nondeterminism and partial or total interpretations of nontermination. For extending these base strongest postcondition monads with side effects such as mutable state, monad transformers do not yield the expected monads, so we instead generalize the base monads to arrows and use arrow transformers. We give a taxonomy of weakest precondition and strongest postcondition monads, for the base monads and for their versions with state, and show that the known relationships between under- and over-approximate triples based on predicate transformers already hold at the level of the predicate transformers themselves. We use the predicate transformer monads to define under- and over-approximate triples and, where possible, Dijkstra monads. Finally, we relate these two specification styles.

### [3] [VulnSAGE: Adjudicating SAST Reports by Connecting LLM Reasoning to Program Structure](https://arxiv.org/abs/2610.23035)
*Jinbao Chen,Zixiang Zhou,Yu Zhang,Yihong Wu*

Main category: cs.SE

TL;DR: VulnSAGE 是一个 SAST 报告裁决系统，将 LLM 推理与程序结构双向连接，用于判定哪些告警是真实缺陷，并进一步生成 PoC 与运行时复现。


<details>
  <summary>Details</summary>
Motivation: SAST 报告标记的操作是否安全依赖项目特定上下文，维护者需人工判断真伪；直接用 LLM 裁决需要决定性代码（常远离报告行）和可被程序分析验证的决策依据。

Method: 以报告为中心的切片恢复被报告操作的依赖及解释其的程序结构（如 helper 作用的调用者对象）；提出中间表示 CLAIM，把模型解读记录为引用所依赖程序关系的语义事实；程序分析校验这些前提，裁决由前提成立的事实推出；两机制共享同一程序图，模型可引用所读代码、检查器可查询这些引用；静态支持的真阳性再指导 PoC 生成与运行时复现。

Result: 在四个语料、五类漏洞的 187 条标注报告上，拒绝 89/97 个误报，保留 85/90 个真实缺陷；相同 PoC 流程下 25 个正判决运行时复现（LLM4SA 仅 3 个）；对 GitHub 前 200 星 C/C++ 项目上五个 SAST 工具的 45,440 条告警，运行时复现 104 个缺陷；维护者回复的 26 个中确认 24 个，含 10 个此前未知缺陷，其中 9 个已修复。

Conclusion: 将 LLM 推理与可检验的程序结构结合，能有效提升 SAST 告警裁决的精度与复现率，并在真实开源项目中发现并修复未知缺陷。

Abstract: Static Application Security Testing (SAST) reports flag operations whose safety depends on project-specific context, and maintainers must decide which reports describe real defects. Large language models (LLMs) can interpret this context, but adjudicating a report with them requires the decisive code, which often lies far from the reported line, and a decision basis that program analysis can check. We present VulnSAGE, an adjudication system for SAST reports that connects LLM reasoning to program structure in both directions. Its report-centered slicer recovers the dependencies of the reported operation together with the program structure that explains them, such as the caller object on which a helper acts. CLAIM, an intermediate representation for report judgments, records each model interpretation as a semantic fact that cites the program relations it assumes. Program analysis checks these premises, and the verdict follows from the facts whose premises hold. Both mechanisms share a program graph, which lets the model cite the code it reads and lets the checker query those citations. Statically supported true positives then guide proof-of-concept generation and runtime reproduction. Across 187 labeled reports from four corpora covering five vulnerability families, VulnSAGE rejects 89 of 97 false alarms and retains 85 of 90 real defects. Under a common PoC procedure, 25 of its positive verdicts reproduce at runtime, compared with three for the LLM-based adjudicator LLM4SA. Applied to 45,440 alerts raised by five SAST tools on the 200 most-starred C/C++ projects on GitHub, it reproduces 104 defects at runtime. Maintainers have confirmed 24 of the 26 defects they have responded to, including ten previously unknown defects, nine of which are already fixed.

### [4] [Where Does the Performance Go? Understanding and Recovering Performance Regressions in C-to-Rust Translation](https://arxiv.org/abs/2610.23044)
*Zhiqiang Yuan,Chong Wang,Zhenhao Zhou,Junwei Liu,Xin Peng*

Main category: cs.AI

TL;DR: 研究 C 到 Rust 转译器 c2rust 的行为保持不等于性能保持问题，识别9类性能退化原因，提出基于LLM的优化规则恢复转译后Rust的性能。


<details>
  <summary>Details</summary>
Motivation: c2rust 等转译器能保持C项目行为地把整个项目迁移到内存安全的Rust，但保持行为并不保证保持性能，此前缺少对这一性能差距的系统研究。

Method: 分析20个真实C项目及其c2rust转译版本；在8个分析用项目上通过对比执行开销剖面、优化后LLVM IR与编译器优化备注，归纳出9类反复出现的性能问题（残留运行时开销、错失编译器优化、C风格源码模式），并给出优化方向。据此提出工具，将问题编码为可复用优化规则：先profile定位热函数并按规则特定模式匹配，再由LLM结合项目上下文校验改写前置条件，改写须通过功能与性能双重验证才保留。

Result: 8个分析项目中，19个操作有12个转译Rust比原C慢逾3%，最多慢62.2%。在12个留出项目的41个操作上，工具在所有测试负载下保持C输出，其中40个操作相比c2rust转译加速，18个快于原始C；在双方均保持C输出的37个操作上，31个优于通用编码智能体Codex，并在41个操作中34个优于无规则指导的自身变体。

Conclusion: c2rust转译存在显著性能损失且可归因于有限类可复用问题；将这些问题的修复经验编码为规则并借助LLM在上下文校验下重写、双验证把关，可有效且安全地恢复乃至超越C的性能，优于通用智能体。

Abstract: Rust is increasingly adopted as a memory-safe successor to C, and transpilers such as \crust{} can migrate entire C projects while preserving their behavior. Preserving behavior, however, does not guarantee preserving performance. We study this gap on 20 real-world C projects and their \crust{} translations. On the eight projects used for analysis, the translated Rust is more than 3\% slower than the original C on 12 of 19 operations, by up to 62.2\%. By comparing execution-cost profiles, optimized LLVM IR, and compiler optimization remarks across each C--Rust pair, we trace these slowdowns to nine recurring performance issues, spanning residual runtime work, missed compiler optimizations, and C-style source patterns, and derive an optimization direction for each. We then present \ourtool{}, an LLM-based approach that encodes these issues as reusable optimization rules to recover the performance of translated Rust. \ourtool{} profiles each project to locate hot functions and matches them against rule-specific patterns. The LLM then checks each rule's rewrite preconditions against the project context before rewriting, and a rewrite is kept only if it passes both functional and performance validation. On 41 operations from twelve held-out projects, \ourtool{} preserves C outputs on all tested workloads and speeds up 40 operations over the \crust{} translations, 18 of which end up faster than the original C. It outperforms the general-purpose coding agent \codex{} on 31 of the 37 operations where both preserve C outputs, and outperforms its own variant without rule guidance on 34 of the 41 operations.

</details>
