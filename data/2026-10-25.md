### [1] [The Reversible Intermediate Language L4, its Type System, and its Bidirectional Small-Step Semantics](https://arxiv.org/abs/2610.31201)
*Torben Ægidius Mogensen*

Main category: cs.PL

TL;DR: 本文提出 L4——一种通用、可逆、线性类型的低级语言，作为可逆编程语言到可逆机器编译的中间语言，取代并推广可逆 SSA 形式 RSSA；文中先给出非形式化说明，再给出形式化类型系统与带方向指示的双向小步语义。


<details>
  <summary>Details</summary>
Motivation: 现有可逆编译缺少通用低层中间表示，RSSA 等可逆 SSA 形式覆盖面有限，故需要一个可推广、可复用的可逆低层中间语言。

Method: 设计线性类型、可逆的 L4 语言（借鉴 HSSA 等低层可逆语言），先非形式化定义，再给出形式化类型系统，以及带方向指示的前向/后向双向小步操作语义，并允许执行中切换方向。

Result: 给出 L4 的非形式化定义、形式化类型系统，以及支持方向切换的双向小步语义。

Conclusion: L4 为可逆语言编译提供了一个通用低层中间语言框架，其形式化语义为可逆执行与类型安全提供了基础。

Abstract: L4 is a generic, reversible, linearly-typed, low-level language intended as an intermediate language for compiling reversible programming languages to reversible machines. L4 is intended to replace and generalise RSSA, a reversible SSA form. Inspiration is drawn from other low-level reversible languages such as HSSA.
  In this paper, we define L4 first informally, and then give a formal type system and a bidirectional small-step semantics for L4: The rules have direction indicators to determine forwards or backwards execution, and the direction can be changed during execution.

### [2] [Finitely Verifiable Segmentation: Decidability for Every Tokenizer with a Finite-State Verifier](https://arxiv.org/abs/2610.30168)
*Nicklas Nidhögg*

Main category: cs.FL

TL;DR: 本文提出「有限可验证的分词策略」概念——用带边界比特标记串上的有限自动机精确接受策略本身的切分——并证明该假设使若干实践中的问题变为可判定，同时给出闭包性、定量性质与开源实现。


<details>
  <summary>Details</summary>
Motivation: 分词实践中许多关键问题（窗口能否认证边界、边界间隙是否有界、掩码是否保持可生成、两策略是否等价）长期靠经验（folklore）处理而无形式保证。作者希望为这类问题提供可判定的理论基础。

Method: 将策略形式化为对每个字节串至多给出一种切分的函数；定义「有限可验证」为：在标记串（字节+边界比特）上的有限自动机恰好接受该策略自身的切分（自动机只判定切分而不计算切分）。据此把四个问题分别归约为 limitedness、coaccessibility、单值 transducer 等价性与码论同步割的精化，并分析该类的边界（严格介于在线可扫描策略与正则域策略之间，内层边界为 Choffrut 类且多项式时间可判定）。证明标记保长，故该类恰为有理分词策略（是正规形而非限制），并证明对流水线常用操作（带标签阶段复合、限制、拆分、字节回退并）封闭，六项判定随之继承，证书可跨阶段迁移（四条定律）。在有理、单射、几乎必然停机的有限状态源下，证明加权段的质量与期望长度为正时的速率均为精确有理数。

Result: 六个判定问题均为可判定；类对流水线操作封闭并继承判定；证书满足四条迁移定律；在所述源模型下质量与速率为精确有理数；Maximal-munch lexing、规范 BPE 与双模 WordPiece 均作为该接口的实例；munch 库实现全部六项判定，每条定理配有可执行检验，所有统计量均为程序自身输出。

Conclusion: 该工作把分词策略的多种实用问题统一到有限可验证/有理分词策略框架下，使之可判定且可组合，并以实际分词器与开源实现验证理论，为分词器的形式化分析提供正规形与工具支撑。

Abstract: A segmentation policy assigns to each byte string at most one segmentation into tokens. Call it finitely verifiable when a finite automaton over marked strings, bytes paired with boundary bits, accepts exactly the policy's own segmentations. The automaton judges a proposed segmentation and need not compute one. The paper shows what that hypothesis buys. Four questions that practice settles by folklore become decidable, whether a window certifies a token boundary, whether the boundary gap is bounded, whether a mask keeps generation completable, and whether two policies are equivalent. The last three specialize limitedness, coaccessibility and the equivalence of single-valued transducers. The first refines the synchronizing cut of code theory, and two more ask whether a certified cut, or the cuts of an inventory, let each piece scan alone. The class sits strictly between the online-scannable policies and those with regular domains, and its inner frontier is Choffrut's and decidable in polynomial time. Markings are length-preserving, so the class is exactly the rational segmentation policies, a normal form rather than a restriction, and what the decisions need is a supplied verifier. The class is closed under the operations pipelines use: composition over a labeled stage, restriction, splitting, and byte-fallback union of literal policies. Each composite inherits the six decisions, and certificates transfer between stages under four laws. Under rational, unifilar, almost surely stopping finite-state sources, each mass of the weighted section is an exact rational, and so is each rate where expected length is positive. Maximal-munch lexing, canonical byte-pair encoding and two-mode WordPiece instantiate the interface, and the munch library implements all six decisions. Every theorem carries an executable check, and every reported statistic is a program's own output.

### [3] [Agentic Verified Optimization of Real-World Software](https://arxiv.org/abs/2610.30188)
*Zhe Ye,Udaya Ghai,Zhizhen Qin,Dawn Song,Soonho Kong*

Main category: cs.SE

TL;DR: 提出"agentic verified optimization"任务：让智能体在产出更快实现的同时给出机器可检验的等价性证明，并在 Lean 4 中于函数与仓库两个层面形式化；为此开发 Aqueduct 框架把 C/C++/Go/Rust 程序迁移为原生 Lean，在 Verina 的 189 个参考实现上为 156 个生成了可证明更快的重写，在 17 个迁移应用中 92 次可证明重写加速了 47/51 个场景。


<details>
  <summary>Details</summary>
Motivation: 现有编码智能体已能通过改算法/数据结构让程序变快，但等价性检查主要依赖测试，智能体会"钻测试空子"——通过测试却不保持原本意图的行为。verified code generation 又受限于规格编写瓶颈，因此希望利用"现有实现即规格"来回避该瓶颈，并结合定理证明的进展实现可信优化。

Method: 在 Lean 4 中把任务形式化为函数级与仓库级（程序既可执行又可推理）；由于现实应用极少用 Lean 编写，构建 Aqueduct 智能体框架，将 C、C++、Go、Rust 程序迁移为原生 Lean，并用与原始程序的差分测试验证每次移植；随后智能体在 Lean 中产出更快的重写并附机器可检验的等价性证明。

Result: Verina 的 189 个参考实现中，智能体为 156 个生成了可证明更快的重写，包括把指数递归替换为动态规划等算法级改动；17 个迁移应用中，92 次可证明重写使 51 个应用场景中的 47 个获得加速。应用层面的增益小于函数层面，说明"选择优化哪些函数"本身是个重要问题。

Conclusion: 当前智能体已能在独立函数和由真实程序迁移而来的应用上完成可验证优化；但应用级收益偏小，函数选择成为关键研究方向。作者最后讨论了剩余挑战以及走向生产环境可验证优化的路径。

Abstract: Program optimization aims to improve performance while preserving behavior. Coding agents can already make programs faster by changing algorithms, data structures, and execution strategies. However, existing equivalence checks mostly rely on tests, which agents have been shown to exploit, passing the tests without preserving the intended behavior. We propose agentic verified optimization, in which an agent produces a faster implementation together with a machine-checked proof of equivalence to the existing one. Because the existing implementation serves as the specification, the task avoids the specification-writing bottleneck of verified code generation, and recent advances in theorem proving make the proofs attainable. We formulate the task at the function and repository levels in Lean 4, where programs can be both executed and reasoned about. Few real-world applications are written in Lean, so we develop Aqueduct, an agentic framework that migrates C, C++, Go, and Rust programs into native Lean, validates each port by differential testing against its original. On the 189 reference implementations in Verina, agents produce faster proved rewrites for 156, including algorithmic changes such as replacing exponential recursion with dynamic programming. On 17 migrated applications, their 92 proved rewrites speed up 47 of 51 application scenarios. These application-level gains are smaller than the function-level ones, making the choice of functions to optimize an important problem. Current agents can thus already carry out verified optimization on both standalone functions and applications migrated from real programs. We discuss the remaining challenges and the steps toward verified optimization in production.

### [4] [TrustedCode: Evaluating Large Language Models for Developing Trusted Code through Automated Program Verification](https://arxiv.org/abs/2610.30432)
*Muhammad Danial,Muhammad Taimoor Khan*

Main category: cs.SE

TL;DR: TrustedCode 是一个利用 LLM 自动验证 AI 生成 Python 代码的开源框架，通过类型检查、翻译为 WhyML(Why3) 并用自动定理证明器验证，在 10 个程序上评估了失败来源。


<details>
  <summary>Details</summary>
Motivation: GitHub 上约 30% 的 Python 贡献由 AI 生成，其可靠性堪忧，需要形式化验证来保证正确性。但形式验证对 Python 支持薄弱（多为 Java/C），且编写形式规约与验证程序正确性对 LLM 仍是难点，实际采用受限。

Method: TrustedCode 用 LLM 完成三步：(i) 对 Python 代码做类型检查；(ii) 借助 Why3 框架将代码翻译为 WhyML；(iii) 使用 Why3 后端自动定理证明器依据形式规约进行验证。并通过 LangGraph 集成思维链（CoT）提示，以识别和缓解 LLM 在规约生成与程序证明上的局限。

Result: 在 10 个复杂度不同的 Python 程序上实验：观察到的错误中 50% 源于领域知识缺失，30% 源于语法不准确，剩余 20% 为语义和类型相关问题。

Conclusion: 结果表明需针对 LLM 引导的 Python 形式验证流程做定向改进（尤其领域知识与语法问题）。TrustedCode 已开源（github.com/mtaimoorkhan/TrustedCode），并提供演示视频。

Abstract: Recent reports, such as "Who is using AI to code?", indicate that approximately 30\% of Python code contributions to GitHub are AI-generated. Given the inherent unreliability of this code, formal verification emerges as a promising approach to establish trust in software correctness. Although leveraging large language models (LLMs) for formal verification has garnered increasing attention, practical adoption remains limited due to the challenges in writing formal specifications and verifying program correctness against them. Existing tools predominantly support verification for languages such as Java and C, with minimal support for Python. We present TrustedCode, an automated framework for verifying AI-generated Python code. TrustedCode uses LLMs to (i) type-check Python code, (ii) translate it into WhyML via the Why3 framework, and (iii) verify it against formal specifications using Why3 back-end automated theorem provers. Our method integrates chain-of-thought prompting through LangGraph to identify and address LLM limitations in specification generation and proving the specified programs. To evaluate TrustedCode, we conducted experiments on ten Python programs of varying complexity. Our analysis reveals that 50\% of the observed errors stem from domain knowledge gaps, 30\% from syntactic inaccuracies, and the remaining 20\% from semantic and type-related issues. These findings underscore the importance of targeted improvements in LLM-guided formal verification workflows for Python. TrustedCode is an open source tool available at: \href{github.com/mtaimoorkhan/TrustedCode}{github.com/mtaimoorkhan/TrustedCode}. The video demonstration is available at: \href{youtu.be/Nr5I2g8ec-s}{youtu.be/Nr5I2g8ec-s}

### [5] [Typed Template Fuzzing](https://arxiv.org/abs/2610.31342)
*Lu Maltsis,Dominik Winterer*

Main category: cs.SE

TL;DR: 提出 Typed Template Fuzzing (TTF)，用 LLM 在预处理阶段把种子转换为“类型化模板”，从而实现无需语言解析器/类型检查器/在线 LLM 查询的语义感知变异式模糊测试，工具 Typos 在 21 种输入语言上平均 96% 变异体有效，半年挖出 135 个 bug（128 个新）。


<details>
  <summary>Details</summary>
Motivation: 复杂输入（结构化/带类型语义的输入）模糊测试长期困难：传统方法要么需大量工程化编码语言约束，要么依赖用户提供文法；近期 LLM 模糊器虽缓解此问题，但引入新缺陷——有的直接用 LLM 生成测试，牺牲吞吐且在 LLM 出错时产生非法输入；有的依赖语言专用解析器、静态分析和 AST 操作库，语言可移植性差。

Method: TTF 是一种轻量级、基于 LLM 的模糊测试方法：仅在预处理阶段调用 LLM，将种子转换为“类型化模板”（typed templates），之后模糊测试期间完全基于模板做语义感知的变异式 fuzzing，无需语言专用解析器、类型检查器或额外的 LLM 查询。同时利用种子与模板之间的对应关系来自动修复 LLM 产生的错误。已在工具 Typos 中实现。

Result: 在 21 种输入语言（含 C、C++、Go、Rust、SystemVerilog、Scala、Java）以及 PyTorch、Qiskit 等库上评估；六个月模糊测试活动中报告 135 个 bug，其中 128 个此前未知；平均 96% 的变异体有效，接近领域专用模糊器的有效率，并显示出相对现有 SOTA 的优势。

Conclusion: 通过在预处理阶段一次性使用 LLM 生成类型化模板，TTF 兼顾了低工程成本、高吞吐与高输入有效性，且不依赖语言专用工具链，具备良好跨语言通用性，实证表现优于现有方法。

Abstract: Fuzzing software with complex inputs has been a longstanding challenge. Traditionally, fuzzers either programmatically encode language constraints, requiring significant engineering effort, or rely on users to declare grammars and constraints. Recent LLM-based fuzzers address these drawbacks but introduce new issues. Some use LLMs for test generation, sacrificing throughput and producing invalid inputs when the LLM makes mistakes. Others rely on language-specific parsers, static analysis, and AST manipulation libraries. We introduce Typed Template Fuzzing (TTF), a lightweight LLM-based fuzzing methodology. The key idea is to use LLMs in a preprocessing step to transform seeds into typed templates. The typed templates then enable semantically aware, mutation-based fuzzing without language-specific parsers, type checkers, or further LLM queries during fuzzing. By exploiting the correspondence between seeds and templates, TTF can moreover repair LLM mistakes. We have implemented TTF in our tool Typos, which we evaluate across 21 input languages, including C, C++, Go, Rust, SystemVerilog, Scala, and Java, as well as libraries such as PyTorch and Qiskit. In a six-month fuzzing campaign, we reported 135 bugs, 128 of which were previously unknown. Perhaps most notably, on average 96% of Typos's mutants are valid, coming close to the validity rates of domain-specific fuzzers. Our evaluation further shows Typos's benefits over the state of the art.

</details>
