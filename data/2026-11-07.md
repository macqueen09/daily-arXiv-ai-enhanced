### [1] [Replay Is a Family of Assertions: Fork-Safety in Event-Sourced Agent Runtimes](https://arxiv.org/abs/2611.06924)
*Yohei Nakajima*

Main category: cs.PL

TL;DR: 论文提出一个可执行的 F# 契约，将事件溯源 agent 运行时中"确定性重放/廉价分叉/血缘"等笼统断言拆分为事实与效应请求、显式调度，并按不同语义层级（投影、严格重放、外部延续、反事实世界观测）评估切点。对 5,540 份公开运行时日志的实证显示多数切点仅满足投影级观察，跨外部效应边界的真实分叉几乎未被验证。


<details>
  <summary>Details</summary>
Motivation: 现有事件溯源 agent 运行时普遍宣称确定性重放、廉价分叉与血缘，但这些实际是"一族断言"而非单一保证：固定日志折叠可以确定，而响应式结算仍对调度敏感；记录的 oracle 结果可实现零调用重放，但原始交互可能已改变成本或世界状态；前缀复制无法撤销被丢弃后缀中的动作。需要理清这些保证的边界。

Method: 构建可执行的 F# 契约，把事实（facts）与效应请求（effect requests）分离，显式化调度，并将切点（cut）相对于四种语义评估：投影观察、严格执行重放、外部延续、以及声明的反事实世界观测。附带保留的反例说明一般结算既不终止也不合流，且"声明不相交写入"无法阻止读/触发干扰。

Result: 在 5,540 份公开运行时日志上：317,296 个投影切点全部满足所述观察；36,251 个切点拆分了模型请求，不具备延续许可；另有 120,969 个为"条件性"（已提交 oracle 结果须从记录中served，不得重执行）。121 次观测到的分叉中，16,625 个保留前缀事件结构零不匹配，但无一跨越外部效应边界。另一个公开离线一致性分叉确实跨越已提交、已记录的 oracle 边界，其生成器验证继承结果被served且未二次调用 fixture oracle，验证器检查收据/日志一致性与基于公开一致性密钥的 fork-bound HMAC 断言。

Conclusion: 将"廉价分叉"重构为一个按属性索引（property-indexed）的语义契约，要求显式的证据与环境前置条件，而非笼统的确定性承诺。

Abstract: Event-sourced agent runtimes commonly claim deterministic replay, cheap forking, and lineage. These are families of assertions, not one guarantee. A fixed-log fold may be deterministic while reactive settlement remains schedule-sensitive; a recorded oracle result can enable zero-call replay while the original interaction still changed cost or world state; and a prefix copy cannot undo an action in a discarded suffix.
  We present an executable F# contract that separates facts from effect requests, makes scheduling explicit, and assesses a cut relative to projection, strict execution replay, external continuation, or a declared counterfactual-world observation. Preserved counterexamples show that general settlement is neither terminating nor confluent and that disjoint declared writes do not prevent read/trigger interference. Against 5,540 public runtime logs, all 317,296 projection cuts satisfy the stated observation, while 36,251 cuts split a model request and do not license continuation; another 120,969 are Conditional because a committed oracle result must be served from the record without re-execution. In 121 observed forks, 16,625 retained-prefix events have zero structural mismatches, but none crosses an external-effect boundary. A separate public offline conformance fork crosses a committed, recorded oracle boundary. Its generator observes that the inherited result is served without a second fixture-oracle call; its verifier checks receipt/log consistency and a fork-bound HMAC assertion under a public conformance key. The result reframes cheap forking as a property-indexed semantic contract with explicit evidence and environment preconditions.

</details>


### [2] [SymFC: Configurable Semantics for All Paths Symbolic Execution in Haskell via Embeddings](https://arxiv.org/abs/2611.07916)
*Robin Webbers,Wind Wong,Klaus v. Gleissenthall*

Main category: cs.PL

TL;DR: SymFC 是一种为 Haskell 设计的新型符号执行方法，通过"嵌入(embedding)"提供可配置的符号语义，并以 GHC 插件形式实现，支持任意类型与值，以及对 IO、指针、硬件描述等的验证。


<details>
  <summary>Details</summary>
Motivation: 现有 Haskell 符号执行工具只能处理语言的子集（排除 IO 等实际应用常用构造），且难以扩展到大程序，不适合通用轻量级验证。其根源在于现有技术对 SMT 基础类型只提供固定的符号语义，难以覆盖更多编程构造与库，也难以针对性能调优符号表示。

Method: 提出 SymFC：通过嵌入提供可配置语义。一个函数的嵌入就是一个普通 Haskell 函数，可使用任意代码及 SMT 原语；利用 Haskell 的 coercions 在 Haskell 类型与其嵌入类型之间透明转换，从而将嵌入整合进类型系统。SymFC 是面向 Haskell 的 all-paths 符号执行引擎，可对 GHC Core 中的任意类型与值进行符号表示，并实现为 GHC 插件。

Result: 在 Haskell 容器库和 iproute 库上验证性质；构建了 IORef、Ptr/ForeignPtr 接口及硬件库 Clash 的嵌入；在 G2 自身基准测试上取得 6.25 倍加速。

Conclusion: 可配置的嵌入式符号语义能有效扩展 Haskell 符号执行的语言覆盖与库支持，并通过针对性的符号表示调优提升性能，使轻量级通用验证更可行。

Abstract: Lightweight methods like QuickCheck have proven to be successful in functional languages and beyond, as they let users specify properties as Boolean functions directly in code. We can replicate some of their benefits for (bounded) proofs via symbolic execution. If we can execute arbitrary functions symbolically, we can specify properties just as easily. Unfortunately, existing symbolic execution tools for Haskell are restricted to a subset of the language that excludes many real-world applications like IO; they also have a hard time scaling to larger programs, making them a poor fit for general purpose lightweight verification. One reason behind these limitations is that existing techniques only offer fixed symbolic semantics for SMT base types. This makes it hard to cover more programming constructs and libraries; it also makes it difficult to fine-tune symbolic representations for better performance.
  We present SymFC, a new symbolic execution method for Haskell that offers configurable semantics via embeddings. An embedding of a function in SymFC is just another Haskell function that can use arbitrary code, as well as SMT primitives. Embeddings make it easy to support new programming constructs and fine-tune symbolic representations for speed. To integrate embeddings into Haskell's type system, we make use of Haskell's coercions, which let us transparently convert between a Haskell type and the type of its embedding. We realize embeddings in SymFC, an all-paths symbolic execution engine for Haskell, which lets us symbolically represent arbitrary types and values in GHC core. We implement SymFC as a GHC plugin, and evaluate it by checking properties of Haskell's container library, and the iproute library. We build embeddings for IORef, Haskell's Ptr/ForeignPtr interface, and the hardware library Clash, and our evaluation reports a 6.25x speedup on G2's own benchmarks.

</details>


### [3] [GUARDTs: Decentralized Access Control for Replicated Data Types](https://arxiv.org/abs/2611.08083)
*Christian Kuessner,Ragnar Mogk,Julian Haas,Annette Bieniusa,Mira Mezini*

Main category: cs.PL

TL;DR: GUARDTs 将细粒度权限直接嵌入应用数据模型，构建无中心权威、支持动态策略演进且能容忍拜占庭副本的可访问控制复制数据类型，并形式化证明其机密性、完整性与可用性，实验表明访问控制开销可忽略。


<details>
  <summary>Details</summary>
Motivation: 现有强最终一致性复制数据类型方案在访问控制上存在空白：或完全不提供访问控制，或委托给可信协调者从而重新引入中心化，或与特定数据类型的构造耦合，且通常假设副本非拜占庭、策略静态不变。

Method: 提出 GUARDTs（Guarded Unforgeable Algebraic Replicated Data Types），把细粒度权限直接嵌入应用数据模型，去除中心权威，支持策略动态演化，并在拜占庭副本环境下工作。

Result: 形式化证明了 GUARDTs 满足机密性、完整性与可用性；实验表明其访问控制在拜占庭容错复制本身成本之上带来的额外开销可忽略。

Conclusion: GUARDTs 表明去中心化复制数据类型的访问控制可以同时做到细粒度、可动态演进、拜占庭容错且低成本，为去中心化软件提供了原则性基础。

Abstract: Replicated data types providing strong eventual consistency offer a principled foundation for developing decentralized software. Yet existing approaches to programming such data types leave access control unresolved: they either provide none at all, delegate it to a trusted coordinator, reintroducing the centralization they were designed to avoid, or tie it to specific data-type constructions, while typically assuming non-Byzantine replicas and static policies.
  We present GUARDTs: Guarded Unforgeable Algebraic Replicated Data Types, which embed fine-grained permissions directly into the application data model, operate without a central authority, support dynamic policy evolution, and tolerate Byzantine replicas. We formally prove that GUARDTs guarantee confidentiality, integrity, and availability and show empirically that their access control adds negligible overhead on top of the cost of Byzantine-resilient replication itself.

</details>

### [4] [NUMA-Torch: Compiler-Driven NUMA-Aware LLM Prefill on Multi-Socket CPUs](https://arxiv.org/abs/2611.07105)
*Thisara Rathnayaka Weerakoon,Ishan Dewpura,Niman Ransindu,Shavin Anjitha,Tharindu R. Patabandi,Sanath Jayasena*

Main category: cs.DC

TL;DR: 提出编译层 NUMA-TP 方案使 TorchInductor 具备 NUMA 感知能力，通过跨插槽权重分片与 CPU 亲和性实现计算与内存本地化，缓解跨插槽访存瓶颈，prefill 最高提速 2.63x。


<details>
  <summary>Details</summary>
Motivation: 大模型权重无法驻留片上缓存，多路 CPU 上的 prefill 受限于可持续 DRAM 带宽而非峰值算力。标准 TorchInductor 分配权重时忽视 NUMA 拓扑（内存库与计算核的亲和性），导致大量权重访问穿越插槽间互连，严重降低每插槽有效带宽。

Method: 在编译器层面将 TorchInductor 改造为 NUMA 感知：把每个 NUMA 插槽视为独立的张量并行分区，提出 NUMA-TP，透明地将权重按插槽分片，并利用 CPU 亲和性调度计算 kernel，使线程池与内存分配严格保持插槽本地化。

Result: 在 GPT-2（117M/345M/762M）、BERT（Small/Large）及 Gemma 3 270M（MQA+GeGLU）上评估。严格数据本地化有效抑制跨插槽流量，双路 Haswell 最高 2.63x、双路 Cascade Lake 最高 1.87x、四路 Haswell-EX 最高 2.27x 的 prefill 加速。

Conclusion: 忽视 NUMA 拓扑是多路 CPU 上 LLM 推理的重要性能瓶颈，编译器级 NUMA 感知张量并行是低侵入、可移植且显著的优化手段。

Abstract: For sufficiently large transformer-based Large Language Models (LLMs), whose parameters cannot be retained in on-chip caches, prefill throughput on multi-socket CPUs is often limited by sustainable DRAM bandwidth rather than peak floating-point throughput. In the standard PyTorch compilation (i.e., TorchInductor) path, model weights are allocated without considering the Non-Uniform Memory Access (NUMA) topology: specifically, the affinity between memory banks and compute cores is disregarded. This causes a substantial fraction of weight accesses to traverse the inter-socket interconnect, severely degrading the effective memory bandwidth available to each socket. We address this bottleneck through a compiler-level solution that makes TorchInductor NUMA-aware. Treating each NUMA socket as an independent tensor-parallel partition, we introduce NUMA-aware Tensor Parallelism (NUMA-TP). This approach transparently shards weights across sockets and schedules compute kernels such that thread pools and memory allocations remain strictly local to their respective sockets using CPU affinity. We evaluate the approach on GPT-2 (117M, 345M, 762M) and BERT (Small, Large), which exercise standard multi-head attention and MLP, as well as Gemma 3 270M, which combines Multi-Query Attention with a GeGLU-gated MLP. By strictly enforcing data locality, our approach successfully mitigates cross-socket traffic, achieving prefill speedups of up to 2.63x on a dual-socket Haswell platform, up to 1.87x on a dual-socket Cascade Lake platform, and up to 2.27x on a four-socket Haswell-EX platform.

</details>
