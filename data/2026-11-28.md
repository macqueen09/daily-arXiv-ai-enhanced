### [1] [SeQLean: Verifying SQL queries using Lean](https://arxiv.org/abs/2611.33181)
*Siddhartha Gadgil,Anirudh Gupta,Ajay Kumar Nair*

Main category: cs.PL

TL;DR: 提出 SeQLean，用 Lean 形式化验证（基于关系代数建模 SQL）来提升自然语言到 SQL 翻译的准确性，通过"证明挑战"检验内部一致性。


<details>
  <summary>Details</summary>
Motivation: 自然语言到 SQL 的翻译缺乏已知正确的参照，无法直接证明正确性；传统等价性检查工具能力有限。

Method: 用关系代数在 Lean 中建模 SQL；采用"证明挑战"：如对同一自然语言查询生成两份翻译（性能优化版与可读版），若都正确则对任意数据库结果一致，用 Lean 证明自动化检查等价性；借助 Mathlib 定理处理算术性质，并考虑底层数据库系统已知性质；提供 HTTP JSON API 以便集成到智能体框架。

Result: 在算术类等价查询上，Lean 因可用 Mathlib 定理而比传统工具更强大；系统可作为验证器接入智能体框架。

Conclusion: 形式化验证与证明挑战为 NL-to-SQL 翻译提供了可行的准确性增强路径，并可与智能体系统集成。

Abstract: We present SeQLean, a system that uses formal verification in Lean to increase the accuracy of translation from natural language to SQL. This is based on modelling SQL in Lean via relational algebras. Since we do not have a translation known to be correct, we cannot directly prove correctness. Instead, we use proof challenges: tests of internal consistency that are unlikely to be satisfied by an incorrect translation. The simplest proof challenge is based on generating two translations of the same natural language query into SQL, ideally with one being optimized for performance and the other for understandability. If two translations are equivalent, they must give the same answer for every database. This can be checked using proof automation in Lean. Using Lean allows us to have essentially arbitrary properties as proof challenges, and also check these (including equivalence) taking into account known properties of the underlying database system. Even for equivalence queries of an arithmetic nature, we show that Lean can be more powerful than traditional tools due to the availability of Mathlib theorems. A JSON API over HTTP allows the verifier to be integrated into agentic frameworks.

### [2] [SentryWard: Formal Verification of Warp-Specialized GPU Kernels](https://arxiv.org/abs/2611.33817)
*Mengdi Wu,Sreeram Vennam,Stephen Mell,Ziwei Zhou,Advay Kadam,Xinhao Cheng,Francois Costa,Alex Aiken,Oded Padon,Zhihao Jia*

Main category: cs.PL

TL;DR: SentryWard：面向warp-specialized GPU内核的形式化验证框架，集成同步验证、数据竞争与资源生命周期分析、函数等价性检查。


<details>
  <summary>Details</summary>
Motivation: 现代GPU内核通过warp specialization重叠异步数据搬运、通用核计算与张量核计算，引入复杂的同步需求；错误的异步顺序会导致数据竞争、资源过早复用和错误结果。测试无法保证正确性（错误非确定性、仅在罕见调度中出现），而现有GPU形式化验证方法对warp-specialized内核支持有限。

Method: 核心思想是证明同步在所有可能执行调度下引入相同的顺序约束。将良同步分析扩展到带异步事务跟踪的现代GPU屏障，推导与调度无关的happens-before图；基于该图验证内存安全并构建符号输出表达式以做函数等价性检查。虽一般假设张量形状与启动配置已知并对循环展开，但用跨线程与张量计算重复结构的紧凑表示提升可扩展性。

Result: 提出SentryWard框架，统一实现同步验证、数据竞争与资源生命周期分析及功能等价性检查，并通过紧凑表示应对循环展开带来的可扩展性挑战；工具已公开。

Conclusion: SentryWard为warp-specialized GPU内核提供了一套基于调度无关happens-before图的统一形式化验证方案，弥补现有技术在异步重叠类内核验证上的不足，并已开源。

Abstract: Modern GPU kernels overlap asynchronous data movement, computation on general-purpose cores (e.g., CUDA cores), and computation on specialized cores (e.g., tensor cores) using warp specialization. These asynchronous-overlap optimizations introduce complex synchronization requirements, where incorrect ordering of asynchronous operations can lead to data races, premature resource reuse, and incorrect results. Testing alone cannot guarantee correctness because such errors are nondeterministic and may only manifest in rare execution schedules, and existing GPU formal verification techniques have limited support for warp-specialized kernels.
  We present SentryWard, a framework for formally verifying warp-specialized GPU kernels. SentryWard integrates synchronization verification, data-race and resource-lifetime analysis, and functional equivalence checking. The key idea is to establish that synchronization induces the same ordering constraints across all possible execution schedules. SentryWard extends this well-synchronization analysis to modern GPU barriers with asynchronous transaction tracking and derives a schedule-independent happens-before graph. It then uses this graph to verify memory safety and construct symbolic output expressions for functional equivalence checking. While SentryWard generally assumes tensor shapes and kernel launch configurations are given and unrolls loops, it uses compact representations of repeated structures across threads and tensor computations to improve scalability. SentryWard is publicly available at https://github.com/gpu-verifier/sentryward.

</details>


### [3] [An Efficient and Uniform CSP Solution Generator Generator](https://arxiv.org/abs/2611.34372)
*Ghiles Ziat,Martin Pépin*

Main category: cs.PL

TL;DR: 本文提出一种专门求解方法，将CSP的解集转化为适合随机采样的表示，从而构建均匀、高效、可迭代自改进的输入生成器，用于基于约束的随机测试。


<details>
  <summary>Details</summary>
Motivation: 基于约束的随机测试需为程序生成满足约束的输入，但手工编写满足约束的生成器非常困难；同时希望生成器对CSP解空间均匀采样且高效。

Method: 提出专用求解方法，生成适合随机采样的表示：基于CSP超图表示的专门传播机制，以及名为bridge-first的自定义分割启发式（与传播机制相配合）。在AbSolute约束求解库上实现原型。

Result: 构建的生成器通用性强、构造上保证均匀性、迭代式且可自改进；在多个真实示例上展示了性能。

Conclusion: 通过专用求解与表示，可高效地为CSP解构造均匀随机生成器，适用于广泛的约束随机测试场景。

Abstract: Constraint-based random testing is a powerful technique which aims at generating random test cases to verify functional properties of a program. Its objective is to determine whether a function satisfies a given property for every possible input. This approach requires firstly defining the property to satisfy, then secondly to provide a generator of inputs able to feed the program with the inputs generated. Besides, function inputs often need to satisfy certain constraints to ensure the function operates correctly, which makes the crafting of such a generator a hard task. In this paper, we are interested in the problem of manufacturing a uniform and efficient generator for the solutions of a CSP. In order to do that, we propose a specialized solving method that produces a well-suited representation for random sampling. Our solving method employs a dedicated propagation scheme based on the hypergraph representation of a CSP, and a custom split heuristic called birdge-first that emphasizes the interests of our propagation scheme. The generators we build are general enough to handle a wide range of use-cases. They are moreover uniform by construction, iterative and self-improving. We present a prototype built upon the AbSolute constraint solving library and demonstrate its performances on several realistic examples.

</details>

### [4] [Cross-Layer Characterization and AI-Assisted Diagnosis of C-to-Rust Performance](https://arxiv.org/abs/2611.33490)
*Dalton Davis,Kunal Pai,Tapti Palit*

Main category: cs.PF

TL;DR: 本文系统刻画C与Rust跨层性能差异，提出AI辅助性能调试器FerroScope，并据此设计保留panic语义的LLVM边界检查提升优化。


<details>
  <summary>Details</summary>
Motivation: C转Rust虽能提升安全性，但运行时安全检查、编译器优化与微架构交互复杂，性能差异难以诊断，常被简单归因于安全检查开销。

Method: 对12个基准的C与Rust实现做跨层（源码、编译优化、动态指令、硬件计数器）系统表征；构建FerroScope整合多源信息进行AI辅助诊断；据此实现LLVM pass，通过带守卫的循环版本化上提冗余边界检查，同时保持panic行为。

Result: 安全检查并非总是主要开销来源；12个基准中8个至少有一个Rust实现性能在C的10%以内或更优。编译器pass使Selection Sort开销从2.95x降至1.00x，Merge Sort从1.43x降至0.91x。

Conclusion: 跨层性能表征与AI辅助诊断能够指导保持安全性的编译器优化，从而促进高效的C-to-Rust迁移。

Abstract: Migrating C code to Rust can significantly improve software security, but understanding the performance implications of such migrations remains challenging. While Rust is often claimed to match C's performance, runtime safety checks, compiler optimizations, and hardware microarchitecture interact in ways that complicate performance diagnosis. We first conduct a systematic cross-layer characterization of 12 benchmarks comprising C implementations and their Rust counterparts. Our study reveals that runtime safety checks do not necessarily dominate performance overhead, as compiler and microarchitectural optimizations often mitigate their costs. Across 8 of the 12 benchmarks, at least one Rust implementation performs within 10% of its C counterpart or outperforms it. Motivated by these findings, we introduce FerroScope, an AI-assisted performance debugger that integrates source-level analysis, compiler optimization remarks, dynamic instruction traces, and hardware performance counters to diagnose performance differences between C and Rust. FerroScope reproduces our manual findings while providing more precise explanations in several cases, including identifying compiler optimizations inhibited by redundant bounds checks. Guided by these diagnoses, we develop an LLVM compiler pass that hoists redundant bounds checks through guarded loop versioning while preserving Rust's panic behavior. The pass enables downstream compiler optimizations, including loop unrolling and conditional-move conversion, reducing Selection Sort's overhead from 2.95x to 1.00x and improving Merge Sort from 1.43x to 0.91x relative to C. Together, our results demonstrate how cross-layer performance characterization and AI-assisted diagnosis can guide safety-preserving compiler optimizations for efficient C-to-Rust migration.

</details>

### [5] [Conditional Work Bounds and Timing Evidence for an Industrial NDT Scan Matcher: Cross-Language Work-Trace Conformance](https://arxiv.org/abs/2611.33159)
*Yuuki Takano*

Main category: cs.DC

TL;DR: 研究Autoware生产版NDT扫描匹配align内核的执行时间输入依赖性，提出三层方法（条件性结构工作包络的性质测试、确定性Rust计数器构造压力见证、冻结见证测量），在10组配对测试上Rust最大观测值610.5 ms均优于C++的988.2 ms。


<details>
  <summary>Details</summary>
Motivation: NDT扫描匹配位于定位关键路径上，其执行时间强烈依赖输入，存在实时性风险；需要区分算法工作量与平台时间，并评估Rust实现能否缩小安全核验证面。

Method: 三层方法：(1) 强制并用性质测试验证条件性结构工作包络；(2) 用确定性Rust计数器构造压力见证；(3) 冻结见证并测量。以逐输入trace定义一致性关系（遍数、处理点数、邻居数、叶节点标识）。C++结果是对移植夹具的观测而非最坏情况搜索；辅以裁剪地图、退化先验回放与带恢复的闭环回放。

Result: 统一三次启动的合成实验中，最大观测值C++为988.2 ms、Rust为610.5 ms，Rust在全部10组配对夹具上最大值更小。返回邻居的夹具上，C++每个点每个导数遍约11次堆分配，Rust对齐路径在其预留包络内零分配。闭环回放显示两引擎在同一路段重新初始化，覆盖带互不重叠。

Conclusion: Rust缩小了安全核验证面，但并非有界执行的必要条件；其unsafe代码、FFI与依赖仍属可信基础。工作包络只约束语言共有的核评估项，叶载荷、实现特有遍历、总工作量和延迟不在该关系内，作者不主张经认证的硬时间界。

Abstract: Normal Distributions Transform (NDT) scan matching has strongly input-dependent execution time on the localization critical path. We study the align kernel of Autoware's production matcher; map loading, preprocessing, and Robot Operating System scheduling are outside the timed scope. Our three-layer method enforces and property-tests a conditional structural work envelope, constructs stress witnesses with deterministic Rust counters, and measures frozen witnesses. It separates algorithmic work from platform time and does not claim a certified hard time bound. A domain-informed construction attains the configured ceiling for the language-common kernel-evaluation term; two archived candidates exercise higher Rust-specific kd-tree traversal at lower common work. Per-input traces define work-trace conformance over passes, processed points, neighbor counts, and leaf identities. Leaf payloads, implementation-specific traversal, total work, and latency remain outside that relation, so C++ results are observations over transferred fixtures rather than a C++ worst-case search. An auxiliary cropped-map, degraded-prior replay exposes the remaining conformance boundary, and a closed-loop replay with recovery shows both engines re-initializing at the same route sections with disjoint coverage bands. In a unified three-boot synthetic campaign, the largest observed values are 988.2 ms for C++ and 610.5 ms for Rust; Rust has the smaller maximum on all 10 paired fixtures. On neighbor-returning fixtures, C++ performs approximately 11 heap allocations per point per derivative pass, whereas the Rust align path allocates none within its reserved envelope. Rust narrows the safe-core verification surface but is not required for bounded execution; its unsafe code, foreign-function interface, and dependencies remain trusted.

</details>
